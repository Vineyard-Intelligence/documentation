    작업 및 실행¶

    Vineyard의 모든 플러그인 실행과 모든 AI 채팅 턴은 단일 클라이언트 측 큐의 작업입니다. 작업 패널은 각 작업의 현재 상태를 표시하고 현재 수행 중인 작업에 적합한 컨트롤 — 중지, 일시 중지, 재개, 취소, 재시도 — 을 제공합니다.

    작업의 작동 방식¶

    플러그인을 실행하거나(AI 채팅에서 메시지를 보내거나) 하면, Vineyard는 작업을 생성하여 단일 클라이언트 측 큐에 배치합니다. 작업은 동시성 제한이 있는 Web Worker 풀에서 실행되므로, 한 번에 몇 개만 실행되고 나머지는 차례를 기다립니다. 동일한 프로젝트를 여러 브라우저 탭에서 연 경우, 단일 탭이 실제로 각 작업을 실행하며(Web Locks API를 통해 조정) 작업이 중복되지 않습니다.

    기본적으로 임시

    작업은 브라우저에 존재합니다. 명시적으로 저장하지 않는 한 실행에 관한 어떤 것도 서버에 기록되지 않습니다. 아래 기본적으로 임시를 참조하세요.

    작업 상태¶

    작업은 최대 7개의 상태를 거칩니다:

    queued  → running | cancelled
running → waiting | paused | succeeded | failed | cancelled
waiting → running | paused | cancelled        (차단이 해제되면 자동 재개)
paused  → queued  | cancelled
succeeded | failed | cancelled = 종료
    상태 의미
    queued 생성되어 빈 워커 슬롯을 기다리는 중. 아직 실행되지 않았습니다.
    running 워커에서 활발히 실행 중이며, 스피너와 (보고된 경우) 진행률이 표시됩니다.
    waiting 시작되었으나 작업 외부의 무언가로 인해 일시적으로 차단됨. 차단이 해제되면 자동 재개됩니다. 대기 중에는 워커 슬롯이 해제될 수 있습니다.
    paused 사용자가 일시 중지했습니다. 자체적으로 재개되지 않습니다.
    succeeded 성공적으로 완료됨 (종료).
    failed 오류로 종료됨 (종료).
    cancelled 완료 전에 사용자가 취소함 (종료).

    세 가지 종료 상태 — succeeded, failed, cancelled — 는 자체적으로 절대 변경되지 않습니다. 작업을 다시 실행하려면 새 작업을 생성합니다(재시도 참조).

    작업이 waiting인 이유¶

    waiting은 단순한 "속도 제한" 일시 중지보다 더 일반적입니다. 작업 패널은 적용되는 차단 종류를 표시합니다:

    하위 상태 의미
    rate_limit 업스트림 API가 작업에 백오프를 요청했습니다(예: Retry-After). 기간이 지나면 자동으로 재개됩니다.
    awaiting_user_input 계속하기 전에 사용자의 결정이나 입력이 필요합니다.
    external_poll 작업이 장기 실행 외부 작업을 폴링하며 진행률 보고를 기다리고 있습니다.
    cors_blocked 브라우저 CORS 제한이 작업이 수행해야 하는 요청을 차단하고 있습니다.
    token_refresh 작업이 계속되기 전에 자격 증명이 갱신되고 있습니다.

    각 경우, 조건이 해결되면 작업이 자체적으로 재개됩니다 — 일반적으로 awaiting_user_input의 경우 요청된 것을 제공하는 것 외에는 아무것도 할 필요가 없습니다.

    상태별 컨트롤¶

    작업 패널의 버튼은 작업 상태에 따라 변경됩니다:

    • 취소 — 시작 전에 큐에서 제거합니다.
    • 중지 — 협력적 중지를 요청합니다 (아래 중지는 협력적입니다 노트 참조).
    • 일시 중지 — paused로 이동합니다.
    • 스피너와 진행률 표시기가 활성 상태임을 보여줍니다.
    • 지금 재개 — 대기를 건너뛰고 카운트다운을 기다리지 않고 즉시 다시 시도합니다.
    • 취소 — 포기합니다.
    • 카운트다운이 자동 재개 시점을 표시합니다 (rate_limit과 같은 시간 기반 차단의 경우).
    • 재개 — 계속하기 위해 다시 큐에 넣습니다.
    • 취소 — 중단합니다.

    succeeded / failed / cancelled의 경우:

    • 재시도 — 작업을 새 작업으로 다시 실행합니다.
    • 다시 열기 (AI 채팅 작업) — 대화를 다시 가져와 계속합니다.
    • 기록에 저장 — 스냅샷을 서버에 지속합니다 (선택적).

    중지는 협력적입니다

    중지는 작업이 정상적으로 종료되도록 요청하며 부분 결과를 보존합니다. Vineyard는 사용자의 중지에 따라 실행 중인 작업 아래에서 워커를 강제 종료하지 않습니다 — 강제 종료는 최후의 백스톱 수단으로 예약되어 있습니다(예: 타임아웃을 초과한 응답 없는 작업).

    재시도는 새 작업을 생성합니다¶

    재시도는 상태가 아닙니다. 종료된 작업을 재시도하면, Vineyard는 어느 작업에서 왔는지 기록하는(원본으로의 retry_of 레퍼런스) 완전히 새로운 작업을 생성합니다. 원본은 그대로 목록에 유지됩니다. 이는 기록을 정직하게 유지합니다: 실행이 실패한 것을 확인한 후, 이전 것을 변형하지 않고 새로운 시도를 자체 항목으로 볼 수 있습니다.

    기본적으로 임시¶

    작업은 계층으로 저장되며, 기본값은 서버에 완전히 보관하지 않는 것입니다:

    1. 탭 메모리 — 탭이 열려 있는 동안 탭 내 저장소에 보관되는 신뢰할 수 있는 사본.
    2. IndexedDB 미러 (선택적) — 동일 브라우저 내에서 새로고침 후 작업이 살아남을 수 있도록 하는 세정된 로컬 캐시. 캐시 전용이며 서버에 동기화되지 않습니다.
    3. 서버 (Postgres) — 기본적으로 아무것도 없음. 기록에 저장을 사용할 때만 Vineyard가 세정된 스냅샷 행을 서버에 기록합니다.

    AI 채팅은 저장하지 않는 한 상태 비저장입니다

    AI 채팅은 더 이상 자동 지속되지 않습니다. 각 턴은 스트리밍 작업이며, 대화와 메시지는 명시적으로 저장하지 않는 한 서버에 기록되지 않습니다.

    협업자 프레즌스¶

    프로젝트를 공유하면, Vineyard는 프로젝트의 실시간 연결을 통해 협업자에 대한 실시간 프레즌스 비콘 — 그들의 상태와 수행 중인 작업의 주제 — 을 표시합니다. 이는 메모리 내 전용이며, 비밀을 전달하지 않고 지속되지 않습니다.
