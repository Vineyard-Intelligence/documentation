    The canvas¶

    The canvas is where a Vineyard project lives: nodes and edges laid out on a graph you can pan, zoom, re-layout, and annotate. This page documents every control available in the on-canvas toolbar and in the top menu bar (Project / Edit / View / Run). Most of them also have a key: see Keyboard shortcuts.

    Two ways to reach the same actions¶

    The view controls are exposed twice, and both stay in sync:

    • On-canvas toolbar — a compact vertical bar pinned to the top-left edge of the canvas, for the controls you reach for most while working.
    • Top menu bar — the Project, Edit, and View menus, which add data and navigation actions alongside the view toggles (a fourth menu, Run, launches plugins and the AI agent — see Running plugins).

    The commands of the menu bar, the toolbar and the right-click menus can also be found by their names in the command palette (⌘K, or Ctrl+K on Windows and Linux), together with the layouts, the types to add a node of and the nodes themselves; see Command palette. The right-click menus' commands act on the selection there. The controls for hiding and saved views are there too: Filter the canvas… opens the toolbar's Filter panel, Show all hidden is the View menu's, Save view… opens the Saved views dialog, and each saved view of the project is a row of its own, such as Saved view: For the report.

    View controls (toolbar + View menu)¶

    Toolbar toggle buttons appear highlighted when on; menu items are checkmarked when on.

    Control Action Surfaces
    Zoom in Zooms the canvas in (1.2×). Toolbar
    Zoom out Zooms the canvas out (0.8×). Toolbar
    Fit view Frames the entire graph so every node is visible. Toolbar, View
    Layout Applies one of the built-in layouts (see below). The active layout is checkmarked. Toolbar, View
    Grid Toggles the background alignment grid. Toolbar, View
    Minimap Toggles the minimap overview panel (bottom-right). Toolbar, View
    Legend Toggles the node-type legend (bottom-left). Toolbar, View
    Snapline Toggles alignment guides shown while dragging nodes. Toolbar, View
    Filter Hides nodes and edges on the canvas by label, type, evidence grade or missing links (see Hiding nodes and edges). Highlighted while a hiding rule is set. Toolbar
    Show all hidden Clears every hiding rule, so the canvas draws everything again. Unavailable while no hiding rule is set. View
    Node table Opens or closes the node table below the canvas; checkmarked while it is open. View
    Reset panel layout Restores the project workspace's panel arrangement to its default. View
    Saved views Keeps the canvas as it is under a name (node positions, zoom, hiding rules and panel layout), and opens a view saved earlier. See Saved views. View

    Reset panel layout resets panels, not the graph

    Reset panel layout restores the surrounding workspace panels (the canvas, side panels, etc.) to their initial split, which closes the node table. It does not re-run a graph layout or move your nodes. To re-arrange nodes, pick a Layout instead.

    Other toolbar buttons¶

    Below the view controls, the toolbar repeats the Edit menu's selection actions (Select all, connected neighbors, outbound, inbound (1 hop), Invert, Select isolated, Clear). It ends with Run plugins, whose tooltip names the scope — "Run plugins on N selected nodes", or "nothing selected" for the whole-graph plugins — and Ask the AI agent; with nodes selected, the AI agent panel opens pre-filled with a question about them. A button that a key also presses ends its tooltip with the key, for example Fit view · F (see Keyboard shortcuts).

    Top menu bar¶

    Project¶

    Item Action
    Project settings… Opens the project settings dialog. General holds the project's name, Leave (collaborators only) and deleting the project (owner only). Access holds the project link, the organization the project belongs to, and who can view it, see it in their project lists and edit it; only the project owner or an owner/admin of its organization can change these, and others see them read-only. People lists the owner and the collaborators; the project owner or an organization owner/admin can invite collaborators by username (View only / Can edit), change their permission and remove them. An invitee gets access only after accepting the invitation, which appears on their dashboard and Projects page; until then they show as "Invitation pending" and the invite can be cancelled. In local mode the dialog has General only.
    Export graph (JSON) Downloads the current graph as a JSON file (see Export graph).
    Import graph (JSON)… Opens a dialog to load an exported JSON file into the project. Every node is created fresh, so importing the same file twice adds every node again. It reads only Vineyard's own export; STIX 2.1 bundles and MISP events come in through a plugin pack, with a review.
    Activity log… Opens the project's activity log, which you can filter and export (see Activity log).
    Add from Marketplace… Opens the Marketplace scoped to this project so you can add plugins, Type Packs and Skill Packs.

    If you opened the project only through its public link, Activity log… is disabled — it is for project members only — and Project settings… shows only the project link; if you are not signed in either, Add from Marketplace… is not shown. In local mode Activity log… is not shown.

    Edit¶

    Item Action
    Select all Marks every node as selected.
    Select connected neighbors (1 hop) Adds the 1-hop neighbors of the current selection to it.
    Select outbound 1-hop nodes Adds the nodes the selection points to (follows only edges leaving a selected node).
    Select inbound 1-hop nodes Adds the nodes that point to the selection (follows only edges entering a selected node).
    Invert selection Selects every unselected node and deselects every selected one.
    Select isolated nodes Selects every node with no edges.
    Clear selection Deselects all nodes and clears the selection count.
    Merge selected nodes… Opens the merge view on the selected nodes (see Merging nodes). Unavailable until two or more nodes are selected.
    Copy labels Copies the selected nodes' labels, one per line (see Copying labels).
    Copy labels, defanged Copies them defanged, so that no address, domain, URL or e-mail in them is a live link.

    The three 1-hop actions add to the selection, so pressing one again walks one more hop; they are disabled until something is selected. The two copy items are disabled until a node is selected.

    Adding a node

    New nodes are created from the Types panel, not from this menu: click one of the types that the project's Type Packs provide. In the command palette, Add node: and the type's name, such as Add node: Domain, does the same.

    Run¶

    Item Action
    Ask the AI agent… Opens the AI agent panel on a new conversation (an open one is kept in Tasks). To return to an earlier conversation, click its row in Tasks.
    Run plugins… Opens the run panel, scoped to the current selection if any nodes are selected.
    Run the last plugins again on the selection Shown once you have run plugins in the project: opens the run panel on the current selection with the last run's plugins ticked and its parameters filled in (see Running the same plugins again).
    (Skill packs) Below a divider, under a Skill packs label: the installed skill packs that can be used here (a pack is listed only when every plugin pack it requires is installed and can run in this app, so in the browser Account & identity pivoting is missing), then the project's own packs, where one whose plugins cannot run is dimmed and marked needs plugins. Picking a pack opens it for reading; it does not run anything (see Skill Packs). The group appears once there is a pack to list; the project owner always sees it, with New skill pack (unavailable once the project has 32 packs of its own) and Import skill pack… at the end (see Your project's own skill packs).

    Right-click menus¶

    • Node — Run plugins… (on this node), Copy labels and Copy labels, defanged (see Copying labels), Duplicate, Connect to… (see Drawing edges), Disconnect all (deletes the edges the canvas draws on the node; edges the canvas filter hides stay), Delete.
    • Edge — Reverse direction, Delete.
    • Selection — right-click empty canvas with anything selected, or a node or edge inside a multi-item selection; the header shows the count (Selected: N nodes, M edges). Run plugins…, Connect to…, Show in node table, Copy labels and Copy labels, defanged (when nodes are selected), Merge nodes… (when two or more nodes are selected, see Merging nodes), Delete (N), Select all, Fit view.
    • Empty canvas (nothing selected, headed Nothing selected — whole project) — Run plugins… on the whole-graph plugins, Select all, Fit view.

    An item that a key also does shows the key on its right: R for Run plugins…, C and ⌘-click (Mac) or Ctrl-click for Connect to…, ⌘C (Ctrl+C) for Copy labels, ⌫ (Mac) or Delete for Delete, ⌘A (Ctrl+A) for Select all and F for Fit view. The edge menu shows none, since a right-click on an edge does not select it and the keys act on the selection.

    Esc closes the menu and nothing under it. Each press of Esc puts away one thing, the front one first: a Connect to… waiting for its target, an open menu (a right-click menu, the Project, Edit, View or Run menu of the menu bar, or the toolbar's Layout menu) or the toolbar's Filter panel, then the panel drawn in front, and last the selection. The panels are drawn in this order, front first: the Review dialog, Run plugins, the Skill pack panel, the AI agent. With the Run plugins panel open over a Skill pack panel, the first Esc closes Run plugins, the next one closes the Skill pack panel, and once nothing is left open Esc clears the selection, like Clear selection. A menu of the menu bar closes on its own, and if focus was in the menu it goes back to the menu's name in the bar. It also closes as soon as focus leaves the bar and its menus: after you click Edit, ? or ⌘/ (the shortcut list) or ⌘K (the palette) closes the menu as the dialog opens, so the next Esc closes only the dialog. An Esc in an open drop-down list, such as a choice in the Properties panel, the node table's type and On the canvas fields, or a plugin parameter with a list of options in Run plugins, closes only the list, and the next Esc closes the panel. The Review dialog closes on an Esc pressed in it, and on one pressed while nothing has focus, as right after Apply, also an Apply from the keyboard after your last click was in the AI agent, Run plugins or Skill pack panel; the panel behind the review stays open. While a review is open, an Esc pressed in Run plugins or the Skill pack panel, or right after you clicked in it, closes that panel and leaves the review open; an Esc from anywhere else leaves both panels as they are. An Esc pressed inside a panel, or right after you clicked in it, goes to that panel rather than to one drawn over it. An Esc typed in a field, or pressed after a click in the Properties panel, leaves the selection alone, and the Esc that finishes a Korean syllable only finishes the syllable. Holding Shift (or another modifier) while you press Esc makes no difference.

    Delete, Delete (N) and Disconnect all ask first, every time, and so does the Delete or ⌫ key on the canvas. The confirmation says what will go, for example Delete 3 nodes and 17 connected edges? This cannot be undone. Deleting a node also deletes every edge connected to it, and the count includes those edges, also the ones the canvas filter hides; the question says how many of them are hidden, as in Delete 1 node and 3 connected edges, 2 of them hidden on the canvas? This cannot be undone. Disconnect all deletes only the edges the canvas draws on the node and leaves the hidden ones, and its question says how many stay: Delete the edge the canvas shows on this node? The 2 hidden on the canvas stay. This cannot be undone. On a node whose every edge is hidden it asks nothing and deletes nothing, and a message says so: This node's 2 edges are hidden on the canvas. Nothing was deleted. Cancel has the focus, so pressing Enter by reflex does not delete; Esc cancels too. A delete cannot be undone. While the project is still loading, deleting a node and Disconnect all are refused, because the edges they would count have not all arrived yet: The project is still loading — delete again once it has finished. When you are signed in to a server, the activity log keeps a line for each deleted node with its type, and for each deleted edge with its label.

    Copying labels¶

    Select nodes and press ⌘C (Ctrl+C on Windows and Linux) to copy their labels, one line per node, ready to paste into a ticket, a chat or a report. The labels are the ones the Properties panel shows, whole, not shortened as on the canvas; a label written over several lines, such as a note's, is copied on one line. A short message says how many labels were copied. Copy labels in the Edit menu, in a node's or a selection's right-click menu and in the command palette does the same, and in the desktop app so does Edit ▸ Copy in its menu bar.

    ⌘C copies the nodes only when nothing else would be copied:

    • while you are typing in a field, ⌘C copies the field's text, as always;
    • while any text on the page is selected, for example in the Properties panel or an AI agent answer, ⌘C copies that text;
    • while a dialog such as Settings or the Review dialog is open, ⌘C does not copy the nodes behind it;
    • only nodes' labels are copied, so with only links selected ⌘C copies nothing.

    Defanged. Copy labels, defanged writes every address, domain, URL and e-mail in the labels so that it is no longer a live link: hxxps://evil[.]example/a, evil[.]example, admin[@]evil[.]example, 203[.]0[.]113[.]7, and [:] for the colons of an IPv6 address. The same goes for one inside a URL, such as a redirect's target: hxxps://evil[.]example/r?u=hxxps://next[.]example/x. An address written in a URL's path or query is part of the URL: https://evil.example/?email=victim@corp.com is copied as hxxps://evil[.]example/?email=victim[@]corp[.]com. A label that is one dotted name is bracketed like a host name whatever its last part is, as long as that part starts with a letter: an internal name such as dc01.corp or nas.lan (dc01[.]corp), and a file name such as invoice.zip or evil.exe (evil[.]exe), but not a number such as 3.14. Anything else, such as a person's name or a hash, is copied as it is, and a label already written defanged is not changed. The AI agent's indicator extraction reads these spellings back. To have ⌘C always copy defanged, turn on Settings ▸ Graph ▸ Defang when copying; it is off by default, because a list pasted into another tool or a block list needs the values as they are.

    Layouts¶

    Applying a layout re-computes node positions and then fits the view.

    Layout Description
    ForceAtlas2 Force-directed layout (Gephi's ForceAtlas2) that pushes nodes apart and pulls connected ones together; built for link-analysis graphs. The default.
    Stress (distance-preserving) Places nodes so that on-screen distance follows the number of hops between them; clusters are less pronounced than in ForceAtlas2.
    D3 Force A D3-based force-directed variant.
    Concentric Arranges nodes in concentric rings; overlap is prevented.
    Circular Places nodes evenly around a single circle.
    Grid Lays nodes out on a regular grid; overlap is prevented.
    Hierarchical (Dagre) Top-down layered layout, good for directed / tree-like graphs.
    Hierarchical (AntV Dagre) AntV's own Dagre variant — also top-down and layered, typically faster on wide graphs.

    Tip

    ForceAtlas2 is the best starting point for an unfamiliar graph. Switch to Stress when how far apart two entities are matters more than which cluster they sit in, and to Hierarchical (Dagre) when the relationships are directional and you want clear layers.

    Overlays¶

    Search¶

    The Search entities… field at the top-right of the canvas finds nodes by type or by any of their property values; typing an AS number such as AS64496 also finds nodes whose ASN is 64496. ⌘F (Mac) or Ctrl+F, or /, jumps to the field; ↑/↓ and Enter pick a result, and Esc closes the list. ⌘G / ⇧⌘G (Ctrl+G / Ctrl+Shift+G) jump to the next and previous result without opening the list. Picking a result selects that node and centers it; a node the canvas hides is shown first. While the project is still loading, an empty result means the node has not arrived yet, not that it doesn't exist.

    Grid¶

    A subtle background grid that follows the canvas as you pan and zoom, giving you a visual reference for aligning nodes.

    Minimap¶

    A translucent overview panel docked at the bottom-right corner. It shows the whole graph in miniature with a viewport rectangle marking your current view — useful for orienting yourself in a large project.

    Legend¶

    A translucent, minimap-style panel at the bottom-left that lists the node types currently present in the graph. Each entry shows a colored swatch matching the node's type color, the type's name (the raw type string if no installed pack defines it), and a per-type count of how many nodes of that type exist. Entries are sorted alphabetically by label. When the graph is empty the legend reads "No nodes."

    Click a row to select every node of that type, or Shift-click to add them to the current selection. Hovering (or focusing) a row dims every other type on the canvas. The eye at the end of a row (shown while you point at the row) hides that type on the canvas; a hidden type's row is dimmed, keeps its count, and shows the type again when clicked.

    Below the types, an Evidence key lists the edge confidence grades present in the project (assessed, asserted, recorded, circumstantial, contested, unassessed), strongest first, each drawn with the same line style (dash, width, opacity) the canvas uses for that grade and with a count. Hover a grade for what it means; Evidence grades lists them all. Click a grade to hide the edges with that grade on the canvas, and click it again to show them; a hidden grade is dimmed and marked with a crossed-out eye, and stays listed even when no edge has it any more.

    The legend reflects whatever Type Packs the project uses — for example, an investigation built on the Infrastructure Type Pack might show counts for infrastructure.ip_address, infrastructure.domain, and so on, each resolved to its Type Pack-defined name and color.

    Snapline¶

    When enabled, dragging a node near another node's edges or center shows alignment guides (vertical and horizontal lines) and snaps the node into alignment. Unlike the grid, minimap, and legend, snaplines have no persistent panel — they appear only while you are actively dragging.

    Parallel edges¶

    When two or more edges connect the same pair of nodes — in either direction — the canvas bends them apart into arcs instead of drawing one on top of the other, so each edge stays visible and individually clickable.

    Hiding nodes and edges¶

    On a large graph, much of what is drawn has nothing to do with the question you are working on. Filter on the toolbar takes it off the canvas without changing the project:

    • Label contains… hides the nodes whose label contains the text, matched as Search matches: case is ignored, and AS64496 also matches a label that is exactly 64496. With Show only matches, every node whose label does not match is hidden instead. The canvas follows the text when you pause typing or press Enter, not at every keystroke, and × clears it at once. Korean is followed once the syllable being typed has its vowel, and text typed with another input method once you confirm it.
    • Hide nodes with no visible links hides every node that no shown edge touches, once the other rules have run, so a node linked only by edges of a hidden grade is hidden too. An edge from a node to itself counts as a link.
    • Types: untick a type to hide its nodes. Nodes stored under another name for the same type, such as its name without the category, are hidden with it. Each type shows how many nodes of it the project has, shown or hidden. A hidden type with no node in the project, such as one hidden from the Types panel or one whose last node was deleted, stays listed with a count of 0.
    • Evidence: untick a grade to hide the edges with that grade.

    An edge is also hidden when either of its ends is. Show all in the panel, or View ▸ Show all hidden, clears every rule.

    The panel opens with the focus in Label contains…, so you can start typing at once, and closing it puts the focus back where it was. The command palette reaches both: ⌘K (Ctrl+K), then Filter the canvas… or Show all hidden, which is greyed with Nothing is hidden on the canvas. while nothing is.

    The legend sets the same rules from the canvas: a type row's eye hides that type, a hidden type's row shows it again when clicked, and a grade row hides or shows the edges with that grade. The Types panel only shows a hidden type, dimmed, with Hidden on the canvas in its tooltip; it has no control of its own for it.

    The footer under the canvas counts what is hidden beside the project's totals, for example Nodes: 400 (120 hidden) | Edges: 900 (310 hidden). The Filter button stays highlighted while a rule is set, and its tooltip says how much is hidden.

    Hiding changes only what the canvas draws:

    • Hidden nodes stay in the project. Plugins, the AI agent, Search, the node table and Export graph still see every node.
    • A hidden node or edge cannot be selected, so Run plugins, Delete (N), Connect to… and the AI agent never act on something the canvas does not show. Select all, Invert, a legend row and the node table's boxes leave hidden nodes out, and a selected node or edge that becomes hidden leaves the selection. Disconnect all leaves a node's hidden edges alone. Deleting a node is the exception: its hidden edges go with it, and the question counts them as hidden on the canvas (see Right-click menus).
    • Going to one node shows it on its own if it is hidden: picking a search result, clicking a node table row, Show on the canvas in the activity log, the AI agent's select_node, and following what a collaborator has selected. The node is selected and centered once it is drawn, unless you select something else before then. The panel counts these as N shown on request, and Hide again puts them back under the rules. Clearing the last rule forgets them too, so a rule you set later hides them like any other node.
    • While a plugin run's changes are under review, the nodes and edges it would change or delete, and the nodes its new edges would connect, are drawn whatever the rules say.
    • A hidden node keeps its place on the canvas and comes back to it when shown again. A layout applied while nodes are hidden arranges only the nodes shown; the hidden ones are placed like newly added nodes when they come back, and showing many of them at once lays out the whole graph again.
    • The rules belong to the open project and last until you leave it or reload the page, unless you keep them in a saved view.

    Saved views¶

    Node positions, the zoom, the hiding rules and the panel layout all start over when you reload the page or open the project again, so an arrangement made for a report or a briefing would be lost. View ▸ Saved views keeps it under a name.

    • Save view… opens the Saved views dialog. Type a name and press Save or Enter. The view keeps where every node is, hidden nodes included; the zoom and the point at the center of the canvas; the hiding rules; and the panel layout. If the project already has a view with that name (ignoring case), saving replaces it, and the button reads Replace.
    • The project's views are listed under Save view…, newest first. Choose one to open it. The dialog lists them too, each with Open and a delete button that asks once more before deleting. In the command palette, Save view… opens the dialog and each view is a row such as Saved view: For the report, which opens it as the menu does.
    • Opening a view puts the nodes back where they were, sets the same zoom on the same point, sets the hiding rules it kept, and restores the panel layout. The canvas shows Opening view… while it redraws.
      • A node the view has no place for, such as one added after it was saved, stays where it is. A node that has no place on the canvas either, such as one added while its type was hidden, is put next to the nodes it links to, or beside the graph if it links to none or there is no room near them, so the rest of the arrangement does not move. A node deleted since is skipped. A message says how many of each there were.
      • If the saved panel layout no longer fits the workspace (it lacks one of the panels, for example), the panels are left as they are and the message says so. The rest of the view still opens.
      • Opening a view changes only what you see, like hiding. Picking a Layout afterwards re-arranges the nodes as usual, and so does the AI agent's Re-arrange the graph after each turn when that setting is on. The saved view itself stays as it was.
    • A view cannot be saved or opened while a layout is being computed or the project is still loading. A message says so; try again once the canvas has settled.
    • Views are kept in this browser, or in the desktop app, per project and filed under the signed-in account; local mode keeps its own. Collaborators do not see them. They are not part of the project or its file, nor of Export graph, and clearing the site's data in the browser removes them. Deleting or leaving the project in Project settings removes its views from this device too, and nothing else does. The views of a project a collaborator deleted, one you were removed from or can no longer open, or one you left on another device stay on this device. Without a signed-in account, for example on a project opened from its link while signed out, no view can be kept.
    • The dialog of any project ends with Other projects while this device holds views of your other projects, with the share of the room they take. Opened, it lists each of those projects by the names of its views, with how many there are, their share of the room and when one was last saved, and a delete button that asks once more before it deletes that project's views from this device. Deleting them there leaves the project itself as it is.
    • A project keeps up to 20 views. Positions take room, so a very large project fits fewer, and the views of all your projects on one device share a limit of their own, so that they leave room for the rest of the app. When a view does not fit, the dialog says so and nothing already saved is changed. When the shared limit, or the browser's own storage, is what is full, the dialog opens Other projects by itself, and deleting another project's views there makes room. When this project's own limit is what is reached, by its 20 views or by their size, only deleting one of its views makes room.

    Node table¶

    View ▸ Node table opens a table of the project's nodes in a pane below the canvas, to sort, filter and pick nodes in bulk. Choose the menu item again, or press × in the pane's title bar, to close it. With several nodes selected, Show in node table opens it on those nodes: the button under N nodes selected in the Properties panel, or the item in the canvas's right-click menu for a selection. The pane can be dragged elsewhere like any other; Reset panel layout closes it.

    Columns¶

    Type, Label, Fields (the node's other values), Links (the number of edges touching the node; 0 means it is isolated), Added and Updated. The label is the one the canvas shows.

    When one type is picked in the type filter, Fields is replaced by a column per field of that type: the fields its Type Pack declares first, in the pack's order, then any other fields the nodes carry, most common first. A field no node fills gets no column, nor does the field the label already shows. Up to 12 field columns are shown; the line above the table says how many more there are, and the keyword filter still searches them.

    Sorting¶

    Click a column header to sort by it, click again to reverse, and a third time to stop sorting by it. Type, Label and the field columns start from A (or the smallest number); Links, Added and Updated start with the largest or newest. Shift-click another header to sort by it as well, after the first: rows the first column leaves equal or empty are ordered by the next. Text sorts as numbers where it has digits, so 10.0.0.9 comes before 10.0.0.10; empty values go last whichever way a column is sorted.

    Filters¶

    • All nodes / From selection — From selection lists the nodes that were selected when the table was opened on them. It does not follow the canvas: clicking through the rows changes the selection but not which rows are listed. When the canvas selection is something else, a refresh button beside it takes the current selection instead.
    • All types — one type only, with the number of nodes of each.
    • Filter by keyword — matches what Search matches (the type or any property value, never a field name, and AS64496 for an ASN of 64496, also inside a list of ASNs), and the label and type name as the table shows them. Esc or × empties the field.
    • Shown and hidden / Shown on the canvas / Hidden on the canvas — appears while the canvas hides nodes, to list only the nodes it draws or only the ones it hides.

    The line above the table counts the rows shown and the nodes selected on the canvas, and how many of the rows the canvas hides. 100 rows are shown per page. While the project is still loading, rows appear as nodes arrive.

    Selecting from the table¶

    The checkboxes are the canvas selection: a box is ticked exactly when its node is selected on the canvas.

    • Tick a box to add its node to the selection; untick it to take the node out. Other selected nodes and edges stay selected. Shift-click a box to do the same to every row from the last one you clicked.
    • The header box adds every row shown, on every page, to the selection, or takes them all out when they are all selected.
    • Click a row to select only that node and center it on the canvas, as picking a search result does. ⌘-click (Mac) or Ctrl-click adds or removes the row, and Shift-click adds the rows from the last one clicked.
    • To copy a value without changing the selection, drag across its text: a click that ends with text selected leaves the selection as it is. A double-click selects the row with its first click, as a plain click does.
    • Select N on canvas makes exactly the rows shown, on every page, the selection. Run plugins, Delete (N), Connect to… and the AI agent then act on them.
    • A node the canvas hides has a crossed-out eye instead of a box, since a hidden node cannot be selected. The header box, Shift ranges and Select N on canvas leave it out. Click its row to show it on the canvas and select it.

    The table only changes the selection, so a participant who can only view the project can use it too.

    Drawing edges¶

    Select the node(s) you want to link from, then ⌘-click (Mac) or Ctrl-click (Windows/Linux) the node to link them to. A small box opens at the click; type the relation (free text, e.g. resolves to) and press Enter. One edge is created from every selected node to the clicked node. Hold Shift while clicking, or press Reverse in the box, to link the other way (clicked node → selection). You can also right-click a node or a selection and choose Connect to…, or press C on the canvas, then plain-click the target. Esc cancels at either step, and nothing is written until you press Enter. An edge is unique per ordered pair of nodes, so pairs that are already connected are skipped and counted as "already connected"; the reverse direction is a separate edge. If nothing is selected, the click only shows a hint to select the nodes first.

    Merging nodes¶

    When one entity is in the project as two or more nodes, such as Example.com. and example.com, or +82 10-1234-5678 and 010-1234-5678, you can merge them into one. Select the nodes, then right-click and choose Merge nodes…, or choose Edit → Merge selected nodes…. In the command palette, either menu's words, merge nodes or merge selected nodes, find Merge nodes…. One merge takes up to 21 nodes: the one kept and 20 folded into it.

    The merge view shows what the merge would do before anything changes:

    • Keep lists the selected nodes with their type and number of links. The node with the most links is picked to start with, because then the fewest links move; pick another to keep that one instead. The node kept stays with every value it has, except a TLP label that another of the nodes marks more strictly: it takes the stricter label. When the selected nodes are of different types, none is picked, and you pick the one of the newer type. Each of the others says how the type packs relate it to the node kept: same identity (its identifying fields are the same value once the type pack folds the spelling), same e164 (or another field the pack marks as the canonical form), same entity via … (through another of the selected nodes), or not identified as the same. For a node the type packs do not identify as the same, a warning says so: merge only nodes you know are one entity, because the merge deletes them.

    • Fields lists each field the kept node has no value for, filled from the first other node that has one, and each conflict: a field the kept node already has where another node has a different value. The value shown is the one the kept node ends with, and the others are not written. To keep the other value, keep that node instead, or change the field after the merge. There are two exceptions, each listed apart:

      • The source fields source_report, created_by, tags, markings and references are combined, as an import combines them: the kept node's values stay and the other nodes' parts are added, so two reports about one domain both stay. Fields lists them under Combined on the kept node, with what each other node adds and what the kept node had. A node whose parts the kept node already holds is no conflict; a value that is not a list, such as an object, still is.
      • tlp: the kept node takes the strictest TLP label among the nodes, as an import keeps the stricter label, and Fields lists that with the label it replaces. A label is never lowered. This holds whichever node is kept, so keeping the node with a laxer label does not keep that label. Another node's laxer label is not written, and Fields lists it apart from the conflicts, under Laxer labels, not written. One label spelled two ways, such as TLP:AMBER and amber, or TLP:WHITE and TLP:CLEAR, is one value and no conflict, but a label with a note beside it, such as TLP:RED (Case 7 only) against TLP:RED, still differs.

      The review's row for the kept node says so, for example tlp raised from TLP:CLEAR to TLP:RED or source_report combined, adding Report B.

    • Links lists every link of the nodes folded into the kept one, and what becomes of it. It moves to the kept node with its own record (who wrote it, its evidence grade and who gave it); or the kept node already has the same link, and the other writer's link corroborates it (when the link on the other node is yours and the kept one is not, the kept one takes your record instead); or the kept node already links that node the same way, by the same writer, and the link on the other node goes with it; or the kept node already links that node in other words, and this link goes with its node; or it joins two of the merged nodes and goes with the merge. A moved link is a new edge, so its history in the activity log starts again. Where links are folded into one, the link that stands takes the strictest TLP label among them, and is never lowered, also when it takes your record; the line ends with, for example, tlp raised to TLP:RED, was TLP:CLEAR.

    The selected nodes must all be in the graph, not waiting in a review, and of one type. Nodes of different types are different kinds of entity. To replace a node of an older type with its newer one, for example an old financial.crypto_address with its cryptocurrency.crypto_address, keep the node of the newer type and tick the box the view then offers. The box names the type that supersedes, the type it supersedes and the node kept; the other node's links move to the node kept and none of its fields do, except a TLP label stricter than the kept node's, which the kept node takes. Picking another node to keep clears the box. Review merge is unavailable while the project is still loading, because the merge has to see every link of the nodes it deletes. It is also unavailable while another change set waiting for review changes one of the nodes being merged or one of their links, because the merge's delete would take that change away; the view names that change set and offers Open that review, where you apply or discard it first.

    Review merge stages the merge as a change set of its own, named Merge, and opens it in the Review dialog. Nothing changes until you apply it there. It is the same merge the AI agent's merge_nodes makes, and the review and the apply treat it the same way: every row says it is part of the merge, unticking a node's delete keeps that node and unticks what would move off it, and when you apply, a node is deleted only after every link and field moving off it has landed, and not at all if it changed after the merge was staged (see Duplicates and merging). Closing the review leaves the merge staged, and its row in Tasks opens it again.

    A grade that rises because a merged node's writer drew the same link shows as Graded by a merge in the Properties panel, not as yours: you decided that the nodes are one entity, not how far to trust the link.

    Inspecting an edge¶

    Click an edge to show it in the Properties panel: its two ends, who wrote its label, its evidence grade with who set it and what it means, Re-verify, the relation and confidence you can change, and what its writer recorded with it. See A link.

    Export graph (JSON)¶

    Project ▸ Export graph (JSON) downloads the project's current nodes and edges as a JSON file named after the project. The export captures a snapshot of the graph data:

    {
  "project": "my-investigation",
  "exported_at": "2026-06-28T12:00:00.000Z",
  "nodes": [ /* … */ ],
  "edges": [ /* … */ ]
}

    While the project is still loading (for example while it re-syncs after a reconnect), export is refused with The project is still loading — export again once it has finished. When the export succeeds, a toast reports how many nodes and edges were written.

    Activity log¶

    Project ▸ Activity log… opens the project's activity log, newest first: who created, changed or deleted which node or edge, and who changed the project and its members. It is for project members, and only when you are signed in to a server; a local project keeps no activity log.

    The drawer reads the log from the server a page at a time. Load older at the bottom reads the next page, as the log stood when the drawer opened or the filters last changed. What happens after that appears at the top as it happens, and the count beside the title is how many rows match, those included.

    Each row shows the action, the account and a summary, then the time in UTC to the second (for example 2026-11-14 09:02:33Z) and how long ago that was. Hover the time to see it with every digit the server stored. Click a row's target, such as node 033rOr…eClw, to see only the rows about it. Show on the canvas, the button after a node's target, selects that node if it is still in the project, and shows it first if the canvas hides it.

    Filters¶

    Filter What it matches
    Actor One account, by its whole name: kim does not match kimberly. A row keeps the name the account had when it was written, so an account renamed since has its earlier rows under the old name. Writes made by the AI agent or by a plugin are recorded under the account of the analyst who applied them, so this filter cannot tell them apart from that analyst's own edits.
    Action Any of the chosen actions, for example Node deleted and Edge deleted.
    Target Nodes, edges, members or the project, or one node or edge. The crosshair button next to it picks the node or edge selected on the canvas.
    Period (UTC days) Rows from the start of the first day to the end of the last, in UTC. Both days are included.

    The filters combine, and Clear filters removes them all.

    If the server does not apply a filter you set, the drawer says so and shows no rows rather than rows the filter did not choose, and an export writes no file. This happens with a server older than these filters, which applies only a single Action. Clear the filters to read the whole log.

    Export the activity log¶

    Export ▸ CSV (spreadsheet) or Export ▸ JSON downloads every row the filters match, not only the rows loaded in the drawer, as activity-<project>-<UTC time>.csv or .json. The file holds the log as it stood when the export began, newest first. Rows written while it reads are left out, and the top of the file gives the time of its newest row (as of). While it reads, the drawer shows how many rows it has read; Cancel stops it and writes no file. One export reads at most 50,000 rows. For a longer log, export a period at a time.

    Each row carries the account's name (actor_name) and its id (actor_id in the CSV, actor in the JSON). The top of each file says which project it is, when and by whom it was exported, up to which row it reads, which filters were used, and what the log does not hold:

    • A summary is stored up to 256 characters.
    • An edit row keeps what it overwrote for at most 20 fields, each cut to 200 characters, and does not keep the new value. If your account cannot edit the graph, the overwritten values are left out of every row.
    • Writes made by the AI agent or by a plugin are recorded under the account of the analyst who applied them.
    • actor_name is the name the account had when the row was written. A renamed account's earlier rows keep the old name, and the name of a deleted account can be registered again, so rows with one name and different ids were written by different accounts. The id is empty for an account deleted since.
    • The session column names the app session the write came from, as the app stated it. The server checks only that it was an open session of the same account.
    • Rows about invitations not yet accepted are included only for the project owner and organization managers.

    Times are written in UTC. In the CSV file the top lines begin with #, and a cell that would begin with =, +, - or @ begins with ' so that a spreadsheet does not run it as a formula. The JSON file keeps those values unchanged.
