    둘러보기 및 설치¶

    이 페이지에서는 마켓플레이스 둘러보기와 설치를 클릭했을 때 일어나는 일을 다룹니다.

    마켓플레이스 둘러보기¶

    마켓플레이스는 완전히 정적인 카탈로그입니다: 모든 팩이 하나의 메타데이터 파일에 있으며, 모든 검색, 필터링, 정렬은 브라우저에서 수행됩니다. 계정, 서버 쿼리, 텔레메트리가 없습니다.

    동일한 컴포넌트와 데이터를 공유하는 두 곳에서 둘러볼 수 있습니다:

    • 이 사이트의 마켓플레이스 페이지 — 공개 읽기 전용 브라우저.
    • Vineyard 앱 내부의 인앱 미러 — 동일한 카드 그리드와 상세 보기로, 설치가 즉시 설치 파이프라인으로 전달됩니다.

    검색 및 필터링¶

    검색 상자는 항목의 이름, 작성자, 설명과 일치하며 입력에 따라 실시간으로 필터링됩니다. 세 가지 측면이 그리드를 좁히며, 이들은 조합됩니다:

    측면 역할
    유형 세그먼트 토글: 전체, Plugin Pack, Type Pack, 또는 Skill Pack.
    카테고리 Type Pack 카테고리의 드롭다운 (예: infrastructure, threat). Type Pack이 보기에 있을 때 표시됩니다.
    인증만 작성자가 인증 목록에 없는 모든 항목을 숨기는 체크박스.

    정렬 드롭다운이 보이는 카드를 재정렬합니다 — 이름순, 또는 인증된 작성자를 먼저.

    카드 읽기¶

    각 카드는 간결한 요약입니다: 아이콘과 이름, 작성자(인증된 경우 ✓ 표시), 한 줄 설명, 그리고 푸터의 배지:

    • Plugin Pack의 경우: 플랫폼 배지(예: web)와 권한 요약 — 선언된 엔드포인트를 호출하는 경우 network, 그래프를 수정할 수 있는 경우 graph write.
    • Type Pack의 경우: schema only 배지(코드 없음, 권한 없음)와 유형 개수.
    • Skill Pack의 경우: 적용되는 노드 유형.

    상세 보기¶

    카드를 클릭하면 상세 드로어가 열립니다. 플러그인의 경우 권한 패널이 요청된 각 스코프를 문장으로 다시 표현합니다 — 예: "그래프: 이 프로젝트의 노드/엣지를 읽고 삭제합니다." 또는 "네트워크: 선언된 외부 엔드포인트를 호출합니다." — 설치 전에 이것을 읽으세요. 드로어에는 팩의 식별자(예: run.vineyard.plugins.cidr_expand), 버전, 라이선스, 그리고 플러그인의 경우 어떤 Type Pack이 먼저 설치되어야 하는지 알려주는 consumes → produces 유형 칩도 표시됩니다.

    인증(✓)의 의미

    인증 ✓는 작성자의 신원을 증명합니다 — 레지스트리가 설정하며 작성자가 아닙니다. 특정 팩의 안전성이나 품질에 대해서는 아무것도 말하지 않습니다: 설치 전에 항상 권한을 직접 검토하세요.

    설치하기¶

    카드에서 설치를 클릭하면 Vineyard가 나머지를 처리합니다 — 작성자의 저장소에서 고정된 커밋으로 팩을 가져와 로컬에 캐시하므로, 이후 오프라인에서도 작동합니다. 어느 시점에도 팩 콘텐츠의 서버 측 복사본은 없습니다.

    플러그인의 경우, 승인 대화상자가 요청하는 권한을 평이한 언어로 나열합니다. 승인하면 플러그인을 프로젝트에서 실행할 수 있게 됩니다.

    Type Pack이나 Skill Pack은 권한을 담지 않으므로 승인 단계가 없으며, 설치가 즉시 완료됩니다.

    팩은 의존성을 자동으로 함께 설치합니다

    입력/출력이 Type Pack의 유형을 참조하는 플러그인은 해당 Type Pack이 설치되어 있어야 합니다 — 마켓플레이스가 이를 해결합니다: Plugin Pack을 설치하면 그 플러그인들이 consume/produce하는 모든 Type Pack도 함께 설치되고, Skill Pack을 설치하면 요구하는 Plugin Pack 그리고 그 Type Pack들까지 끌어옵니다 (스킬 → 플러그인 → 타입팩, 카탈로그에서 한 번에 해석). 이미 설치된 팩은 건너뛰고, 카탈로그에 없는 의존성은 실행 시 실패하는 팩을 남기지 않도록 설치 자체를 차단합니다. 플러그인은 있는데 Type Pack이 설치되지 않은 프로젝트는 해당 Skill Pack을 설치하는 순간 누락분이 복구됩니다.

    프로젝트에 설치하기¶

    설치는 프로젝트 단위로 소속되며, 계정 단위가 아닙니다 — 프로젝트의 모든 협업자가 동일한 어휘와 도구를 받습니다. 설치 세트를 변경할 수 있는 사람은 프로젝트 소유자뿐입니다. 팩을 제거하면 프로젝트에서 빠지고 로컬 캐시 바이트도 삭제됩니다. 실행은 결코 지속되지 않으므로 정리할 실행 기록이 없습니다.
