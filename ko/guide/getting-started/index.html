    시작하기¶

    첫 실행 안내: Vineyard 앱을 열고, 프로젝트를 만들고, 마켓플레이스에서 Type Pack과 플러그인을 설치한 다음, 그래프에서 플러그인을 실행합니다. 핵심 루프는 프로젝트 → 유형 → 플러그인 → 임시 실행입니다.

    1. 앱 열기¶

    Vineyard는 오늘 브라우저에서 실행됩니다. 로그인하면 프로젝트 목록에 도착합니다.

    플러그인과 Type Pack은 클라이언트에서 실행됩니다: 서버는 그래프를 저장하고 협업을 중개하지만, 플러그인 코드는 절대 실행하지 않습니다.

    2. 프로젝트 열기 또는 만들기¶

    프로젝트는 그래프(노드 + 엣지), 협업자, 설치된 팩 세트를 소유합니다.

    • 기존 프로젝트: 목록에서 선택하세요.
    • 새 프로젝트: 만들기를 선택하고 이름을 지정하면 캔버스로 바로 이동합니다.

    설치는 프로젝트에 속합니다

    팩은 계정이 아닌 프로젝트에 설치되므로, 해당 프로젝트의 모든 협업자가 동일한 어휘와 도구를 받습니다. 설치 세트를 변경할 수 있는 사람은 프로젝트 소유자뿐입니다.

    3. 캔버스 만나기¶

    캔버스는 작업 표면입니다 — 팬, 줌, 배치할 수 있는 노드/엣지 그래프. 메뉴, 컨텍스트 메뉴, 사이드 패널의 전체 둘러보기는 캔버스를 참조하세요.

    새 프로젝트에는 아직 엔티티 유형이 없습니다. 그것을 해결하는 것이 Type Pack입니다.

    4. 마켓플레이스 열기¶

    캔버스에서 프로젝트 → 마켓플레이스에서 추가…를 선택하세요. 이름/작성자/설명으로 검색하고, 유형, 카테고리, 인증 상태로 필터링한 다음, 카드를 열어 세부 정보를 확인하세요. 전체 둘러보기는 둘러보기 및 설치를 참조하세요.

    5. Type Pack 추가 (엔티티 유형)¶

    Type Pack은 노드가 될 수 있는 엔티티 유형(및 선택적 엣지 유형)을 정의하는 순수 JSON입니다. 플러그인의 입력과 출력이 Type Pack 유형으로 표현되므로, 플러그인보다 먼저 설치하세요.

    마켓플레이스에서 Type Pack으로 전환하고 Infrastructure (run.vineyard.typepacks.infrastructure)를 설치하세요. infrastructure.ip_address, infrastructure.netblock, infrastructure.domain 같은 엔티티 유형을 제공합니다. 자세한 내용은 Type Pack을 참조하세요.

    6. 플러그인 설치¶

    플러그인은 그래프를 읽고/쓰는 JavaScript로, 필요한 권한에 대한 승인을 요청합니다. 좋은 첫 설치 두 가지:

    • CIDR Expand — 순수 계산, 네트워크 없음. infrastructure.netblock 노드를 그 안의 개별 infrastructure.ip_address 노드들로 바꿉니다. (Infrastructure를 먼저 설치한 이유입니다.)
    • Chaos Reference Pack — 실행 루프를 배우기 위한 여섯 개의 작은 플러그인 (Korean Roulette, Thanos Snap 등)을 담은 하나의 번들.

    설치하면 승인 대화상자가 플러그인의 권한을 평이한 언어로 나열하므로, 승인하기 전에 무엇을 건드릴 수 있는지 알 수 있습니다. 전체 내용은 둘러보기 및 설치를 참조하세요.

    7. 실행하기¶

    플러그인이 무엇을 소비하는지에 따라 실행 방식이 결정됩니다:

    • 노드 유형을 대상으로 함 (예: CIDR Expand) → 일치하는 노드의 우클릭 메뉴에 나타나며, 해당 노드가 입력으로 미리 바인딩됩니다.
    • 전체 그래프를 대상으로 함 (예: Korean Roulette) → 전역 플러그인 실행 메뉴에서 실행합니다.

    플러그인이 입력을 받으면 작은 실행 전 양식이 나타납니다(CIDR Expand의 경우 CIDR 블록 — 우클릭한 노드에서 이미 채워져 있음). 확인하면 실행이 시작됩니다.

    작업 패널에서 지켜보세요. 작업은 queued → running → {succeeded | failed | cancelled} 상태로 이동하며, 실행 중 중지, 일시 정지, 진행률 컨트롤을 제공합니다. CIDR Expand의 경우 캔버스에 새 infrastructure.ip_address 노드가 나타나는 것을 볼 수 있습니다.

    8. 실행은 임시입니다¶

    기본적으로 실행에 대한 어떤 것도 서버에 저장되지 않습니다 — 결과를 유지하려면 완료된 작업에서 명시적 저장 동작을 사용하세요. 자세한 내용은 작업 및 실행을 참조하세요.
