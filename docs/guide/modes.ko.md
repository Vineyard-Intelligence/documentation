# 로그인 모드와 로컬 모드

Vineyard는 Vineyard 서버에 로그인해 브라우저의 웹 앱이나 데스크탑 앱으로 쓸 수도 있고, 계정 없이 데스크탑 앱이 프로젝트를 이 컴퓨터의 폴더에 보관하는 로컬 모드로 쓸 수도 있습니다. 로컬 모드는 데스크탑 앱에만 있으며, 이 페이지에서는 두 방식의 차이와 전환 방법을 설명합니다.

## 무엇이 다른가 {#what-differs}

| | 로그인 모드(웹 앱 또는 데스크탑 앱) | 로컬 모드(데스크탑 앱만) |
| --- | --- | --- |
| **실행 위치** | [app.vineyard.run](https://app.vineyard.run)의 웹 앱 또는 데스크탑 앱. | 데스크탑 앱에서만. 웹 앱에는 로컬 모드가 없으며, 로그인 화면에는 대신 **Get the desktop client**가 있습니다. |
| **데스크탑 전용 플러그인, 명령, 파일** | 데스크탑 앱에서만. 웹 앱에서는 데스크탑 전용 플러그인이 **Run plugins** 패널의 **Desktop only** 아래에 표시되며 실행할 수 없고, 에이전트도 명령을 실행하거나 파일을 다룰 수 없습니다. | 사용할 수 있습니다. |
| **계정** | Vineyard 계정. **Settings**에 **Account** 그룹(**Profile**, **Password**, **Two-factor**, **Active Sessions**)이 있습니다. | 없습니다. 로그인, 가입, 비밀번호 재설정 화면이 없고, **Settings**에 **Account** 그룹이 없습니다. |
| **프로젝트 저장 위치** | Vineyard 서버. 같은 서버의 같은 계정이면 웹 앱과 데스크탑 앱에 같은 프로젝트가 보입니다. | 선택한 폴더에 프로젝트마다 `<id>.vineyard.json` 파일 하나로 저장되며, 파일에는 그래프, 설치된 팩, 프로젝트 자체 Skill Pack이 들어 있습니다. **Settings → About → Storage**에는 **Local workspace**가 표시됩니다. Vineyard 서버에는 아무것도 저장되지 않습니다. |
| **설정** | 계정에 저장되므로 웹 앱과 데스크탑 앱에서 같은 설정을 씁니다. **This device only**로 표시된 항목은 예외입니다. | 이 컴퓨터의 앱 안에 보관됩니다. |
| **동기화와 백업** | 프로젝트가 서버에 있으므로 어디서 로그인하든 그대로 있습니다. 서비스가 테스트 중인 동안에는 계정과 프로젝트가 예고 없이 초기화될 수 있습니다. | 동기화도 백업도 없으니 폴더를 직접 백업하세요. 프로젝트 파일은 앱이 붙인 이름 그대로 두세요. 이름을 바꾼 프로젝트 파일이나 같은 폴더에 복사해 둔 사본은 프로젝트로 열리지 않습니다. 파일 이름이 여전히 `.vineyard.json`으로 끝나면 **Projects** 페이지에 건너뛴 파일로 표시됩니다. |
| **공유와 협업** | **Project settings → Access**에 프로젝트 링크가 있고, 누가 프로젝트를 보고, 목록에서 보고, 편집할 수 있는지 정합니다. **Public (anyone with the link)**로 두면 링크를 가진 누구나 프로젝트를 열 수 있습니다. **People**에서 사용자 이름으로 협업자를 초대하며, 초대받은 사람은 수락한 뒤에 접근 권한을 얻습니다. 프로젝트 멤버에게는 누가 프로젝트를 열고 있는지 보입니다. | 없습니다. 로컬 프로젝트에는 링크, 협업자, 초대, 프레즌스가 없습니다. |
| **조직** | 사이드바의 **Organizations** 페이지. | **Organizations** 페이지가 없습니다. |
| **프로젝트 설정** | **General**, **Access**, **People**. | **General**만 있습니다. |
| **대시보드** | **Continue**, **Since your last visit**, **Activity**, 모든 프로젝트에서 엔티티를 찾는 검색창, 그리고 기다리는 초대. | **Continue**만 있습니다. |
| **Messages 패널** | 프로젝트를 편집할 수 있는 사람들이 함께 쓰는 프로젝트 채팅입니다. 그 밖의 사람에게는 *Chat is visible to people who can edit this project.*가 표시됩니다. | Messages 패널이 없습니다. |
| **활동 로그** | **Project ▸ Activity log…**가 프로젝트의 활동 로그를 엽니다(프로젝트 멤버 전용). | 활동 로그를 남기지 않으며, 메뉴 항목도 표시되지 않습니다. |
| **공지사항** | 상단 바에 서비스의 상단 고정 공지가 표시됩니다. | 없습니다. |
| **마켓플레이스 설치** | Vineyard가 운영하는 서비스를 호출하는 팩에는 **Vineyard service** 칩이 붙으며, 다른 팩과 똑같이 설치됩니다. | 그런 팩(예: Telegram)에는 대신 **Account required** 칩이 붙고, **Install**은 비활성화되어 *Needs a Vineyard account — sign in to use this pack*이 표시됩니다. 나머지 팩은 평소처럼 설치됩니다. |
| **Vineyard 서비스를 호출하는 플러그인** | 서비스가 내 Vineyard 세션으로 호출을 인증합니다. | 서비스에 Vineyard 계정이 필요하다는 오류와 함께 호출이 실패합니다. |
| **AI 에이전트 모델 프로바이더** | 직접 고른 프로바이더와 키를 쓰며, 모델 호출은 앱에서 프로바이더로 바로 갑니다. 웹 앱에서는 웹 페이지의 호출을 허용하지 않는 프로바이더에 *desktop only*가 표시되며, 그런 프로바이더는 웹 앱에서 실행할 수 없습니다. 데스크탑 앱에서는 모든 프로바이더를 쓸 수 있습니다. | 데스크탑 앱과 같습니다. 모든 프로바이더를 쓸 수 있습니다. |
| **웹 검색과 페이지 읽기** | 기본 검색 프로바이더는 **Serper, through the Vineyard server**이고 **Brave, through the Vineyard server**도 있습니다. 둘 다 에이전트의 검색어를 Vineyard 서버를 거쳐 보냅니다. 웹 앱에서는 데스크탑 전용 프로바이더가 회색으로 비활성화됩니다. 기본 페이지 읽기 방식에서 데스크탑 앱은 각 페이지를 먼저 직접 가져오고, 웹 앱은 각 URL을 리더 서비스 r.jina.ai로 먼저 보냅니다. | 두 서버 옵션이 회색으로 비활성화됩니다(*needs the Vineyard server*). 기본값처럼 그중 하나가 선택되어 있으면 에이전트는 **DuckDuckGo**로 검색합니다. 페이지 읽기는 데스크탑 앱과 같습니다. 프로바이더와 페이지 읽기 방식은 [웹 검색과 페이지 읽기](tasks.md#web-search-and-page-reading)에 정리되어 있습니다. |
| **키와 시크릿** | 이 기기에 계정별로 보관되며 Vineyard 서버로 전송되지 않습니다. 플러그인 키는 웹 앱에서는 탭을 닫을 때까지만 남고, 데스크탑 앱에서는 컴퓨터의 키체인으로 암호화됩니다(암호화할 수 없는 컴퓨터에서는 그 세션 동안만 남습니다). LLM 키와 검색 엔진 키는 이 기기에 암호화되지 않은 채 보관됩니다. | 데스크탑 앱과 같은 방식으로, 로컬 모드 전용 공간에 보관됩니다. 로그인 상태에서 저장한 키는 여기서 보이지 않고, 여기서 저장한 키는 로그인했을 때 보이지 않습니다. |

두 모드 모두 플러그인은 이 컴퓨터의 앱 안에서 실행되고, 에이전트의 모델 호출은 AI 프로바이더로 바로 가며, 프로젝트를 열 때마다 설치된 팩을 레지스트리와 대조합니다.

## 모드 전환 {#switching-modes}

### 로그인 화면에서 로컬 모드로 {#from-the-sign-in-screen-to-local-mode}

1. 데스크탑 앱에서 **Sign in** 화면으로 갑니다. 로그인한 상태라면 먼저 아바타 메뉴에서 **Log out**을 고르세요.
2. **Work locally, without an account**를 누릅니다.
3. 프로젝트를 보관할 폴더를 고르거나, 대화상자에서 새로 만듭니다. 대화상자를 취소하면 아무것도 바뀌지 않습니다.
4. **Restart to work locally**에서 **Restart now**를 누릅니다. **Later**를 고르면 다음에 앱을 시작할 때 로컬 모드로 열립니다.

### 다시 서버로 {#back-to-a-server}

1. 사이드바 아래쪽의 **Connect to a server**를 누르거나, **Settings → About → Storage**에서 **Connect to a server**를 누릅니다.
2. 앱이 바로 다시 시작되고, 전환하기 전에 쓰던 서버에 연결됩니다. **Desktop Settings… → Backend**의 주소는 바뀌지 않습니다. 로그인 화면이 나오면 로그인하세요.

### 데이터는 어떻게 되나 {#what-happens-to-your-data}

- 아무것도 옮겨지거나 삭제되지 않습니다. 서버의 프로젝트는 서버에 그대로 있고 로컬 모드에서는 보이지 않으며, 폴더의 프로젝트 파일도 그대로 있고 서버에 연결할 때 업로드되지 않습니다.
- 프로젝트를 다른 모드로 가져가려면 한 모드에서 **Project ▸ Export graph (JSON)**으로 내보낸 뒤, 다른 모드에서 프로젝트를 만들고 **Project ▸ Import graph (JSON)…**으로 가져옵니다. 파일에는 노드와 엣지만 들어 있으므로 팩은 다시 설치하고, 프로젝트 자체 Skill Pack은 따로 옮기세요([프로젝트 자체 Skill Pack](skillpacks.md#custom-skill-packs) 참고).
- AI 대화, 프로젝트 메모리, 키, 설정은 로컬 모드와 각 계정에 따로 보관됩니다. 전환한 뒤에는 지금 모드의 것이 보이고, 다시 전환하면 이전 것이 돌아옵니다.
- **Work locally, without an account**는 누를 때마다 폴더를 묻습니다. 같은 폴더를 고르면 같은 프로젝트가 다시 보입니다.
