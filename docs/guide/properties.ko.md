# Properties 패널

**Properties** 패널은 캔버스에서 선택한 것을 보여 줍니다. 노드 하나, 링크 하나, 또는 선택한 노드의
수입니다. 노드의 값을 읽고 편집하고, 필드를 더하거나 지우고, 노드를 한 페이지로 읽고, 링크를 얼마나
믿을 수 있는지와 누가 그렸는지를 보는 곳입니다. 오른쪽, Tasks 위에 있습니다([작업 화면
그림](getting-started.md#3-meet-the-canvas)의 7). 다른 패널처럼 다른 곳으로 끌어
옮기거나 크기를 바꿀 수 있고, **Reset panel layout**을 누르면 제자리로 돌아갑니다.

## 패널이 보여 주는 것 {#what-the-panel-shows}

| 선택한 것 | 패널에 나오는 것 |
|---|---|
| 없음 | *No node selected* |
| 노드 하나 | 이름, 유형, 필드([노드](#a-node)) |
| 노드 여러 개 | *N nodes selected*와 **Show in node table**. 누르면 그 노드들로 [노드 표](canvas.md#노드-표)가 열립니다. |
| 링크(엣지) 하나 | 양 끝, 라벨, 증거 등급, 함께 기록된 값([링크](#a-link)) |

패널은 클릭한 순간의 모습이 아니라 지금 저장된 모습을 보여 줍니다. 패널이 보여 주던 노드를 내가
지우든 다른 사람이 지우든 패널은 *No node selected*로 돌아가고, 선택한 링크가 지워지면 *This link no
longer exists*가 남습니다.

## 보기 전용 {#view-only}

프로젝트를 볼 수는 있지만 편집할 수 없을 때(공개 링크로 열었거나 편집 권한이 없는 협업자일 때)는
패널 맨 위에 *View only*가 표시됩니다. 마우스를 올리면 *Only people who can edit this project can
change these values.*가 나옵니다. 로컬 모드에서는 언제나 편집할 수 있습니다.

- 값은 같은 방식으로 보이고, 행 아래에서 펼치고, 찾을 수 있지만 바꿀 수는 없습니다.
- [값 메뉴](#the-value-menu)로 복사, 그래프 검색, 노드로 이동, URL 열기를 할 수 있지만 새 노드는
  제안하지 않습니다.
- **+ Field**가 나오지 않고, 어떤 필드도 지울 수 없으며, JSON 보기의 **Edit**는 비활성화됩니다.
- 링크 패널에서는 **relation**과 **confidence**를 바꿀 수 없습니다. **Re-verify**는 그 자체로는
  아무것도 쓰지 않으므로 그대로 있습니다. 그것이 제안한 변경을 적용하려면 편집 권한이 필요합니다.

모든 쓰기는 서버가 판단합니다. 프로젝트를 연 채로 편집 권한을 잃으면 프로젝트를 다시 읽을 때까지
패널이 편집할 수 있는 것처럼 보일 수 있으며, 거기서 바꾼 값은 *Not saved: you do not have write access
to this project.*와 함께 거부되고 저장된 값으로 돌아갑니다.

## 노드 {#a-node}

패널 위쪽에는 노드가 무엇인지 나옵니다.

- 유형의 아이콘과 색, 그리고 캔버스에 표시되는 이름.
- **ID**, 그리고 저장된 그대로의 **Type**(`infrastructure.domain`).
- 이 탭을 연 뒤 누군가 그 노드를 쓴 것을 보았다면 *Last written by …*와 얼마 전인지. 마우스를 올리면
  그 쓰기가 온 세션이 있으면 함께 나옵니다. 새로고침하면 사라집니다. 노드를 누가 만들고 바꿨는지는
  [문서 보기](#document-and-json-views)가 활동 로그에서 읽어 옵니다.
- 패널이 노드를 보여 주는 방식을 바꾸는 **Table**, **Document**, **JSON**. 고른 보기는 이 기기에
  기억됩니다.

### 그리드 {#the-grid}

**Table**은 노드의 필드를 그리드로, 한 행에 하나씩, 왼쪽에 이름, 오른쪽에 값으로 보여 줍니다.

- 노드의 유형이 선언한 필드가 Type Pack에 적힌 순서대로 먼저 나옵니다. 값이 없어도 나옵니다. 이름
  뒤의 `*`는 유형이 필수로 정한 필드라는 표시입니다.
- 노드가 가졌지만 유형이 선언하지 않은 필드는 그 뒤에, **Added fields**와 그 필드를 선언하지 않은
  유형의 이름 아래에 모입니다. 플러그인, 가져오기, AI 에이전트, [**+ Field**](#adding-and-removing-fields)가
  쓴 필드이며, 유형은 그 값을 검사하지 않습니다.
- 각 이름 앞의 작은 표시는 값이 지금 무엇을 담고 있는지를 나타냅니다. 유형이 선언한 것과 다를 수
  있어서, 숫자로 선언했지만 텍스트를 담은 필드에는 `T`가 붙습니다.

    | 표시 | 값 |
    |---|---|
    | 대시 | 없음: 저장된 값이 없습니다 |
    | `T` | 텍스트. URL, 날짜, 해시, 주소도 텍스트입니다. |
    | `#` | 숫자 |
    | 스위치 | 참 또는 거짓 |
    | `{}` | 객체 |
    | `[]` | 목록 |

- 이름에 포인터를 올리면 이름 전체와 유형이 그 필드에 붙인 설명이 나옵니다. 값에 올리면 값 전체가
  나옵니다. 목록은 한 줄에 한 항목, 구조 값은 들여쓴 JSON입니다. 긴 값은 16줄에서 끊고 남은 양을
  적습니다(`… 2,340 more characters`). 값을 편집하는 동안에는 값의 풍선 도움말이 열리지 않습니다.
- 두 열 사이의 선을 끌면 이름 열을 넓힐 수 있습니다.
- 유형이 아무것도 선언하지 않고 노드에도 아무 값이 없으면 *No properties defined for this type*이
  나옵니다.

노드의 Type Pack이 설치되지 않았거나 불러오지 못했어도 그리드는 노드가 가진 필드를 모두 값에 따라
보여 줍니다. 이때는 유형이 어떤 필드를 선언하거나 필수로 정하는지 알 수 없으므로 **Added fields**
제목이 나오지 않고, 저장할 때 아무 값도 검사하지 않습니다.

### 필드 찾기 {#finding-a-field}

그리드 위의 **Find a field or value**와 **Hide empty**는 그리드에 보이는 필드를 줄입니다. 둘 다 노드를
바꾸지 않으며, *View only*로 표시된 패널에도 있습니다.

- **Find a field or value**는 입력한 내용이 이름이나 값에 들어 있는 필드만 보여 줍니다. 대소문자는
  가리지 않고, `first seen`으로 `first_seen`을 찾습니다. 목록은 항목 하나하나로, JSON은 키가 아니라
  값으로 맞춰 보며, `AS64496`은 숫자 `64496`을 가진 필드도 찾습니다. **Esc**나 **×**로 비웁니다.
  입력한 내용은 다른 노드를 골라도 남으므로, 한 필드를 여러 노드에서 차례로 볼 수 있습니다.
- **Hide empty**는 아무것도 담지 않은 필드를 숨깁니다. 값이 없거나, 빈 텍스트, 빈 목록, `{}`인
  필드입니다. `0`과 `false`는 값입니다. 유형이 필수로 정한 필드(`*`)는 남습니다. 이 선택은 이 기기에
  기억됩니다.
- 지금 편집 중인 필드는 비우거나, 입력한 내용이 더는 맞지 않아도 입력칸을 나갈 때까지 화면에 남습니다.
- 값을 바꾼 필드는 입력칸을 나간 뒤에도 찾기 칸이나 **Hide empty**와 상관없이 변경이 저장될 때까지
  남습니다. 값이 거부되거나 서버에 연결하지 못하면 입력한 내용 그대로 남으므로 고칠 수 있습니다.
- 캔버스에서 누른 **Enter**나 **F2**는 찾기 칸이나 **Hide empty**가 그 필드를 빼더라도 노드 라벨이
  보여 주는 필드를 엽니다. 그 행은 입력칸에 있는 동안 보입니다.
- 숨긴 필드가 있으면 그리드 아래 줄에 보이는 필드 수, 맞지 않는 필드 수(**Clear**는 찾기 칸을
  비웁니다), 빈 필드 수(**Show**는 **Hide empty**를 끕니다)가 나옵니다.

## 값 읽기 {#reading-values}

그리드는 값을 선언된 유형만이 아니라 값이 무엇인지에 따라 보여 줍니다. URL은 호스트를 강조하고,
해시는 줄여서 알고리즘을 옆에 적고, 텍스트 필드 하나에 담긴 목록은 항목으로 나눠 보여 줍니다.
바뀌는 것은 표시 방법뿐입니다. 저장된 값은 사용자가 편집하기 전까지 그대로입니다.

값 끝의 화살표(**›**)를 누르면 그 행 아래에 값 전체를 보는 보기가 열립니다.

| 값 | 그리드 | 행 아래 보기 |
|---|---|---|
| 긴 텍스트(`description`, `bio`, 게시글) | 첫 줄과 나머지 줄 수(`+3 lines`). | 줄바꿈을 지킨 전체 텍스트, **Find**와 **Copy**. |
| 텍스트 필드 하나에 담긴 목록(`name_servers`, `open_ports`, `user_ids`, `tags`) | 앞쪽 항목을 칩으로, 항목 수와 함께. | 한 행에 한 항목, URL이면 그 호스트. **Copy, one per line**, **Copy defanged**, **Edit as text**. |
| URL | 저장된 그대로의 URL, 호스트는 강조. 브라우저가 읽지 못하는 URL에는 `unreadable`, 호스트 앞에 사용자 이름이나 비밀번호가 있으면 `credentials` 배지가 붙습니다. | scheme, 호스트(퓨니코드면 유니코드 형태도), 포트, 경로, 디코딩한 쿼리 파라미터 하나하나, fragment. **Defanged**를 켜면 그리드에서도 `hxxps://example[.]com`처럼 보입니다. 같은 호스트를 가진 다른 노드. |
| 해시 | 앞 8자와 뒤 8자, 그리고 속성 이름이나 길이로 읽은 알고리즘(`MD5`, `SHA-1`, `SHA-256`, `mmh3`, `ssdeep`, `TLSH`…). 알고리즘은 라벨일 뿐이며 아무것도 계산하지 않습니다. | 전체 해시, **Copy**, 대문자로 적힌 16진 해시에는 **Lower case**, 같은 값을 가진 다른 노드. |
| IP 주소나 CIDR 블록 | 값, `v4` 또는 `v6`, 그리고 `private`, `loopback`, `documentation` 같은 특수 용도 대역. 호스트 주소로 적은 블록에는 `host bits set`이 붙습니다. | 주소의 표준 표기, 또는 블록의 네트워크, 넷마스크, 첫 주소와 끝 주소, 크기. 같은 /24(IPv6는 /64)에 있거나 블록 안의 주소를 가진 다른 노드. |
| 이메일 주소 | 도메인 강조. | local part, `+` 뒤의 태그, 도메인(유니코드 형태도). |
| 크기, 개수, 금액(`size_bytes`, `*_count`, `followers`, `balance`) | 천 단위 구분. 크기는 KiB, MiB, GiB로도, 금액은 노드의 통화와 함께. | — |
| 코드: 탐지 규칙, armored 키, 원본 레코드, 명령행 | 고정폭 글꼴로 첫 줄. | 줄 번호, YARA, Sigma, PGP armor, WHOIS 강조(8,000자까지), **Find**, **Wrap**, **Copy**, **Download**, 그리고 **Save**를 눌러야 저장되는 코드 편집기 **Edit**. 편집기는 열 때 코드가 8,000자 이하면 강조해서, 그보다 길면 강조 없이 열립니다. 편집하다가 8,000자를 넘으면 색만 없어지고 편집기, 커서 위치, 실행 취소는 그대로입니다. |
| 암호화폐 주소 | 주소 형식이 속한 체인과 체크섬 결과(EIP-55, Base58Check, Bech32, Bech32m). Solana 주소와 모두 소문자인 EVM 주소에는 체크섬이 없고, Monero의 체크섬은 검사하지 않습니다. 체크섬은 맞지만 버전 바이트가 Vineyard가 아는 체인이 아닌 Base58Check 주소(Bitcoin Gold, Dash)는 체인 없이 `checksum ok`로 표시합니다. | 형식, 체인, 노드의 currency나 network 필드가 말하는 값, 블록 탐색기 링크. 링크는 노드가 지정한 네트워크의 탐색기이고, 노드에 네트워크가 없으면 주소 형식이 속한 체인의 탐색기입니다. 탐색기 서버가 사용자의 IP 주소, 시각, 조회한 주소를 알게 되므로 링크는 열기 전에 확인을 받습니다. |
| JSON | 한 줄짜리 JSON과 편집용 **{ }**([JSON 값](#json-values)). | 트리: 접고 펴기, 키를 눌러 경로 복사(`rdap.events[0].action`), **Find**, 들여쓴 JSON을 보는 **Raw**. |

레거시 Bitcoin 주소는 Bitcoin Cash와 Bitcoin SV에서도 같은 문자열이고, EVM 주소는 모든 EVM 체인에서
같은 문자열이지만 체인마다 다른 계정입니다. 그래서 노드가 주소 형식과 다른 네트워크를 지정했거나,
Vineyard에 탐색기가 없는 네트워크(Ethereum Classic, Bitcoin Gold, Dash 등)를 지정했거나, 여러 체인이
같이 쓰는 주소에 `evm`이나 `unknown`만 적혀 있으면 탐색기 링크를 제공하지 않습니다. 그 이유는 행 아래
보기에 적힙니다.

값의 종류는 선언된 유형, 속성 이름, 값 자체로 판별하므로 흔치 않은 값에서는 틀릴 수 있습니다. 틀려도
바뀌는 것은 표시 방법과, 텍스트 필드 하나에 담긴 목록이라면 에이전트의 `aggregate_values`가 그 항목을 세는
방법뿐입니다. 다른 노드 목록은 노드 패널에만 있고 Review 대화상자에는 없습니다.

### 시각, 선택지, 참·거짓 {#times-choices-and-true-or-false}

이런 종류의 값은 유형이 기대하는 것과 달라도 저장된 그대로 보입니다.

- **날짜와 시각**(`datetime`)은 적힌 그대로 보이고, 그 아래 줄에 어떻게 읽히는지가 나옵니다. UTC로
  나타낸 순간과 얼마 전인지(`2026-11-14 09:02Z · 2h ago`), 인증서 만료일처럼 1분 넘게 앞선 시각이면
  UTC 시각만, 시간대가 없는 날짜·시각이면 EXIF 시각(`2021:12:14 11:58:18`)을 포함해 `no timezone`입니다.
  날짜만 있는 값, epoch 숫자, 일반 텍스트에는 이 줄이 없습니다. 저장할 때 아무것도 변환하지 않습니다.
- **날짜**(`date`)는 날짜 선택기로 고릅니다. 시각을 담은 `date` 필드나 선택기가 보여 줄 수 없는 날짜는
  날짜·시각처럼 적힌 그대로 보입니다.
- **선택지**(`enum`)는 유형이 나열한 값 가운데 고르며, 입력해서 목록을 좁힐 수 있습니다. 유형이 나열하지
  않은 값이 저장되어 있으면 그 값 그대로 `(not in type)` 표시와 함께 남고, 마우스를 올리면 *Not one of
  the values this type lists.*가 나옵니다. 유형이 필수로 정하지 않은 필드에만 값을 지우는 **×**가
  있습니다.
- **불리언**(`boolean`)은 스위치입니다. 값이 없는 필드는 거짓으로 보이지 않습니다. `—`와 함께 `true`나
  `false`를 고르게 되며, 마우스를 올리면 *Not collected. Nothing is stored here, which is not the same as
  false.*가 나옵니다. `yes`처럼 둘 다 아닌 값은 저장된 그대로 보입니다. 고르면 `true`나 `false`가
  기록됩니다.
- 가져오기로 들어온 `AS13335`처럼 텍스트를 담은 **숫자** 필드는 그 안의 숫자만이 아니라 텍스트
  그대로 보입니다.
- **줄바꿈이 있는 값**은 유형이 무엇을 선언했든 한 줄 입력칸에 넣지 않으므로 줄이 사라지지 않습니다.
  여러 줄 입력칸에 나오고, 한 줄에 하나씩 적은 `name_servers`처럼 줄들이 목록으로 읽히는 텍스트
  필드라면 항목으로 나옵니다.

## 값 편집하기 {#editing-a-value}

- 값을 누르거나 **Tab**으로 옮겨 가면 편집할 수 있습니다. 긴 텍스트와 코드는 그 자리에서 커집니다.
- 텍스트 입력칸, 숫자 입력칸, 날짜 선택기, 날짜·시각, 긴 텍스트, 코드에서 **Esc**는 저장된 값으로
  되돌리고 입력칸을 나갑니다. 한 줄 입력칸(텍스트, 숫자, 날짜, 날짜·시각)에서는 **Enter**로 저장합니다.
  긴 텍스트와 코드에서는 **Enter**가 줄바꿈이고, **⌘Enter**(Mac)나 **Ctrl+Enter**로 저장합니다.
  입력칸을 나갈 때도 저장됩니다. 한글 음절을 끝내는 **Enter**나 **Esc**는 음절만 끝냅니다.
- 선택지(`enum`, 또는 `true`와 `false`), 목록, 색 선택기에서도 **Esc**는 입력칸을 나가며, 옆에 열린
  Run plugins나 Skill pack 패널을 닫지 않습니다. 선택지 목록이 펼쳐져 있으면 Esc는 그 목록만 닫습니다.
  색 선택기에서는 반쯤 입력한 색 대신 저장된 색으로 되돌립니다.
- 입력하는 동안 입력칸은 처음 누른 그대로 유지됩니다. 지금까지 입력한 내용이 URL, 주소, 목록으로
  읽혀도 바뀌지 않고, 입력칸을 나가면 그 종류로 표시됩니다.
- URL, 이메일 주소, IP 주소, 해시, 암호화폐 주소를 편집하는 동안에는 입력칸 아래 줄에 값의 문제가
  표시됩니다. 유형의 규칙이나 실패한 체크섬입니다. 저장 여부는 유형의 규칙이 정합니다.
- *View only*로 표시된 패널에서도 값을 같은 방식으로 보고 펼칠 수 있지만 편집할 수는 없습니다.

값을 편집하는 입력칸은 선언된 유형과 담긴 값에 따라 정해집니다.

| 필드에 담긴 것 | 편집하는 곳 |
|---|---|
| 텍스트 | 한 줄 입력칸. |
| 유형이 `text`로 선언한 텍스트, 또는 줄바꿈이 있는 값. 목록으로 읽히는 값은 빼고(아래 참조) | 여러 줄 입력칸. 줄 끝은 값이 원래 쓰던 대로 남으므로, 원본 WHOIS 레코드의 CRLF는 편집한 뒤에도 CRLF입니다. |
| 숫자 | 숫자 입력칸. 텍스트를 담은 숫자 필드에서는 입력한 내용이 숫자 표기(`13335`)일 때만 숫자로 저장되고, 그렇지 않으면 이유와 함께 거부됩니다. |
| 선택지(`enum`) | 유형이 나열한 값의 목록. |
| 불리언(`boolean`) | 스위치. 둘 다 아닌 값을 담은 필드라면 `true`와 `false` 가운데 고르는 목록. |
| 날짜(`date`) | 날짜 선택기. 선택기가 보여 줄 수 없는 값이면 텍스트 입력칸. |
| 날짜와 시각(`datetime`) | 텍스트 입력칸과, 그 아래 어떻게 읽히는지를 적은 줄. |
| 색(`color`) | 16진 색 선택기. |
| 텍스트·숫자·참거짓의 목록 | 항목([목록](#lists)). |
| 객체, 또는 객체를 담은 목록 | 한 줄짜리 JSON과 **{ }**([JSON 값](#json-values)). |

텍스트 필드 하나에 담긴 목록은 항목 단위로 편집합니다. 항목을 입력하고 **Enter**를 누르거나 **×**로
지웁니다. 저장할 때는 값이 원래 쓰던 구분자(한 줄에 하나 또는 `, `)로 다시 이어 붙입니다. 항목을
끝으로 옮기지 않고 그 자리에서 고치려면 행을 펼쳐 **Edit as text**를 누릅니다. 그러면 입력칸이 저장된
텍스트 그대로가 됩니다. **Edit as entries**를 누르면 항목 편집으로 돌아갑니다.

### 목록 {#lists}

목록의 항목은 칩으로 보이고, 뒤에 **Add…**가 있습니다. 항목을 입력하고 **Enter**를 누르면 더해지고,
항목의 **×**를 누르면 지워집니다. 바꿀 때마다 바로 저장됩니다. 입력한 항목은 다른 곳을 클릭하거나
**Tab**으로 입력칸을 나갈 때도 더해지고, **Esc**를 누르면 버려져 아무것도 더해지지 않습니다. 텍스트
입력칸 하나에 적은 목록도 같습니다. 유형이 목록(`array`)으로 선언한 필드는
아직 아무것도 없을 때도 이렇게 편집합니다.

목록은 항목의 종류를 지킵니다.

- `[80, 443]`을 담은 `open_ports`처럼 숫자 목록에서는 숫자로 읽히는 항목이 숫자로 저장되므로, `8080`은
  숫자 `8080`으로 들어갑니다. `8080/tcp`처럼 숫자로 읽히지 않는 항목은 텍스트로 저장되고, 그러면 목록에
  둘이 섞입니다.
- 텍스트 목록에서는 숫자로만 된 항목도 텍스트로 남습니다. `"01"`은 `"01"` 그대로이고 `1`이 되지
  않습니다.
- `true`와 `false`의 목록에서는 `true`와 `false`가 참·거짓으로 저장됩니다.
- 종류가 섞인 목록에는 지킬 종류가 없으므로, 편집하면 모든 항목이 텍스트로 저장됩니다.
  `[80, "http"]`는 `["80", "http"]`가 됩니다. 숫자를 지키려면 이런 목록은
  [JSON 보기](#document-and-json-views)에서 편집하세요.
- 빈 목록에는 지킬 종류가 없으므로 더한 항목은 텍스트가 됩니다. 숫자 목록을 새로 시작하려면
  [JSON 보기](#document-and-json-views)에서 쓰세요.
- 9,007,199,254,740,991보다 큰 정수는 텍스트로 남습니다. 숫자로 저장하면 끝자리가 사라지기
  때문입니다.

### JSON 값 {#json-values}

객체, 또는 텍스트·숫자·참거짓이 아닌 것을 담은 목록은 한 줄짜리 JSON으로 보입니다. 포인터를 올리면
들여쓴 전체가, 행을 펼치면(**›**) 트리가 나옵니다. 줄 끝의 **{ }**를 누르면 JSON 편집기가 열리며, 연
순간 저장된 값으로 시작합니다.

- **Save**는 텍스트가 올바른 JSON일 때만 값을 씁니다. 그렇지 않으면 편집기가 이유와 함께 열린 채로
  남고, 아무것도 저장되지 않습니다.
- 9,007,199,254,740,991보다 큰 정수나, 숫자로 나타낼 수 없을 만큼 큰 수(`1e400`)는 거부됩니다.
  JavaScript가 이미 반올림했으므로 `18446744073709551616`은 `18446744073709552000`으로 저장될 것이기
  때문입니다. 자릿수를 모두 지키려면 `"18446744073709551616"`처럼 따옴표로 감싸세요.
- **Cancel**, **Esc**, 바깥 클릭은 저장하지 않고 편집기를 닫습니다.
- 편집기는 열 때 JSON이 8,000자 이하면 강조해서, 그보다 길면 강조 없이 열립니다. 편집하다가
  8,000자를 넘으면 색만 없어지고 같은 편집기에 커서 위치와 실행 취소가 그대로 남습니다.
- 저장한 값은 다른 값처럼 유형의 규칙으로 검사합니다([저장과 검사](#saving-and-checks)).

[JSON 보기](#document-and-json-views)도 노드의 `data` 전체를 같은 두 규칙으로 편집합니다.

## 저장과 검사 {#saving-and-checks}

- 텍스트, 숫자, 날짜, 날짜·시각은 입력칸을 나가거나 **Enter**(긴 텍스트와 코드에서는 **⌘Enter**나
  **Ctrl+Enter**)를 누를 때 저장됩니다. 스위치, 선택지, 목록 항목, 색은 바꾸는 즉시, JSON 값은 편집기의
  **Save**를 누를 때 저장됩니다.
- 값이 노드가 이미 가진 값과 같으면 아무것도 쓰지 않으므로, 필드를 누르거나 Tab으로 지나가기만 해서는
  아무것도 기록되지 않습니다.
- 바꾼 값은 유형이 그 필드에 선언한 종류, 허용 값, 패턴이나 범위로 검사합니다. 통과하지 못한 값은
  저장되지 않고, 필드와 문제를 알리는 메시지가 나옵니다. 예를 들어 *country_code does not match the
  format its type requires: kr*이며, 유형에 그 필드의 설명이 있으면 이어서 나옵니다. 입력한 내용은
  입력칸에 그대로 남으므로 고칠 수 있고, **Esc**를 받는 입력칸이라면 되돌릴 수도 있습니다
  ([값 편집하기](#editing-a-value)).
- 바꾼 필드만 검사합니다. 편집할 때 필수(`*`) 필드를 채우라고 요구하지 않으므로, 플러그인이 필수 필드
  없이 저장한 노드도 편집할 수 있습니다. 유형이 선언하지 않은 필드와, Type Pack이 설치되지 않은 노드의
  필드는 검사하지 않습니다.
- 프로젝트에 쓸 권한이 없어 서버가 저장을 거부하면 *Not saved: you do not have write access to this
  project.*가 나오고 필드는 저장된 값으로 돌아갑니다. 그 밖의 거부에는 *Could not save this
  property.*가, 서버에 연결하지 못하면 *Unable to reach the server.*가 나오며, 두 경우 모두 입력한
  내용은 남습니다.

검사 목록 전체는 [앱이 노드 데이터에서 검사하는 것](../develop/typepacks.md#what-the-app-checks-on-node-data)에
있습니다.

## 다른 사람이 같은 노드를 편집할 때 {#when-others-edit-the-same-node}

- 패널은 저장된 노드를 따라갑니다. 협업자가 저장한 변경, 적용된 리뷰, AI 에이전트의 쓰기는 노드를 다시
  선택하지 않아도 도착하는 대로 패널에 나타납니다.
- 입력 중인 필드는 건드리지 않습니다. 그 사이 그 필드에 변경이 도착해도 입력하던 내용을 덮어쓰지
  않습니다. 내 저장이 반영되면 그 필드는 다시 노드를 따라갑니다. **Esc**를 받는 입력칸에서 **Esc**는
  협업자의 변경까지 포함해 지금 저장된 값으로 되돌립니다.
- 저장할 때는 바꾼 필드만, 저장을 보내는 순간 이 탭이 가진 노드 위에 얹어 씁니다. 다른 사람이 다른
  필드에 한 변경은 남습니다.
- 두 사람이 같은 필드를 바꾸면 나중 저장이 이기며, 그리드는 경고하지 않습니다.
  [JSON 보기](#document-and-json-views)는 다른 사람이 바꾼 필드를 덮어쓰기 전에 묻습니다.
- 짧은 틈이 하나 남아 있습니다. 서버는 저장할 때마다 노드의 `data` 전체를 바꾸므로, 내 저장을 보낸
  뒤 서버가 적용하기 전 그 순간에 다른 사람이 저장한 변경은 다른 필드에 대한 것이라도 사라질 수
  있습니다. 필드를 더하거나 지울 때와 JSON 보기에서 저장할 때도 같은 방식으로 `data` 전체를 씁니다.

## 값 메뉴 {#the-value-menu}

값에 포인터를 올리면 칸 끝에 **⋯**가 나타납니다(터치스크린에서는 늘 보입니다). 누르면 그 값에 대한
메뉴가 열립니다.

- **Copy**는 저장된 값을 줄바꿈까지 그대로 복사하고, 구조 값은 들여쓴 JSON으로 복사합니다.
  **Copy defanged**는 디팡하면 값이 달라질 때 나옵니다. scheme은 `hxxp`, `hxxps`, `fxp`로, 호스트와 URL
  경로의 점은 `[.]`로, 이메일의 `@`는 `[@]`로, IPv6 주소의 콜론은 `[:]`로 바뀌고, URL 안의 URL(리다이렉트
  대상)도 디팡됩니다. 호스트 이름과 이메일 주소는 최상위 도메인과 상관없이 디팡되므로 `dc01.corp`나
  `user@evil.zz`도 디팡됩니다. **Copy refanged**는 값이 디팡된 채 저장되어 있을 때 나옵니다. 디팡한
  복사본을 리팡하면 원래 값이 그대로 돌아옵니다.
- **Search the graph**는 값을 리팡해 캔버스의 검색 입력란에 넣고 결과를 보여 줍니다. 그래서
  `evil[.]example`로 `evil.example`을 찾습니다. 256자 이하의 한 줄 값과 숫자에 나옵니다.
- 값 전체가 지표 하나(IP 주소나 블록, 도메인, scheme이 있는 URL, 이메일 주소, 전화번호, 해시, CVE id,
  Bitcoin·TRON·EVM 주소)이면, 메뉴가 그 값이 가리키는 노드를 제안합니다.
    - 같은 식별자의 노드가 이미 그래프에 있으면 **Go to …**가, 설치된 플러그인 가운데 그 유형을 받는
      것이 있고 프로젝트를 편집할 수 있으면 **Select it and run plugins…**가 나옵니다. 그래프에는 값을
      적힌 그대로도, 해시는 대문자로도 찾아보므로, 대문자로 저장된 SHA-256이나 생략 없이 쓴 IPv6 주소도
      같은 노드로 찾습니다. 도메인의 `domain_name`처럼 노드 자신의 식별자를 담은 필드에는 어떻게 적혀
      있든 둘 다 나오지 않습니다.
    - 검토를 기다리는 변경 세트가 이미 그 노드를 만들고 있으면 **Review the staged …**가 나옵니다.
    - 그 밖에는 **New … node…**가 나옵니다. 노드와, 값을 담은 노드에서 이어지고 필드 이름(`name_servers`)을
      라벨로 단 링크를 스테이징하고 Review 대화상자를 엽니다. 적용하기 전에는 아무것도 기록되지 않으며,
      링크는 체크를 해제할 수 있습니다. 링크는 사용자가 쓴 것으로 기록되고, Tasks 창에 리뷰를 다시 여는
      행이 남습니다. 설치된 플러그인 가운데 그 유형을 받는 것이 있으면 **Run plugins**가 함께 흐리게
      표시되며, **Review the staged …**와 함께일 때도 같습니다. 플러그인은 그래프에 있는 노드에서
      실행되므로 새 노드를 먼저 적용해야 합니다.
    - 해시는 그리드와 같이 필드 이름과 함께 읽습니다. `tx_hash`의 64자리 값은 트랜잭션 id이고,
      `imphash`나 `ja3`의 32자리 값은 지문이므로 둘 다 파일 해시로 제안하지 않습니다. 이름에 fingerprint나
      thumbprint가 든 필드의 값(인증서의 `fingerprint_sha256`, PGP 키의 `fingerprint`)과, `hash`로
      선언되어 자기 노드를 식별하는 필드의 값(DOM 해시의 `hash_value`)도 마찬가지입니다. 각각 파일이
      아니라 그 인증서, 키, 페이지의 다이제스트입니다. SHA-256은
      `threat.file_hash`가, MD5나 SHA-1은 `threat.indicator`가 됩니다.
    - 비트코인, TRON, EVM 주소는 주소 형식이 정하는 네트워크의 Cryptocurrency 팩
      `cryptocurrency.crypto_address`가 됩니다. `bc1…`은 `bitcoin`, `T…`는 `tron`, `0x` 주소는
      `evm`, 옛 형식의 `1…`·`3…` 주소는 `unknown`입니다. 이 마지막 형식은 비트코인, 비트코인 캐시,
      비트코인 SV에서 같은 문자열이기 때문입니다. Financial 팩만 있고 Cryptocurrency 팩이 없는
      프로젝트에는 대신 옛 `financial.crypto_address`를 통화와 함께 제안합니다. 두 팩이 모두 없으면
      항목은 흐리게 표시되고 `cryptocurrency.crypto_address`를 알려 줍니다.
    - 그 유형을 정의하는 Type Pack이 설치되어 있지 않거나 유형의 형식이 값을 거부하면, 항목은 이유와
      함께 흐리게 표시됩니다.
- **Open in browser…**는 `http://`나 `https://`로 저장된 URL에 나오며, 열기 전에 확인을 받고 브라우저가
  접속할 호스트를 보여 줍니다. 호스트가 퓨니코드이면 유니코드 형태도 함께 보여 주므로, 비슷하게 생긴
  호스트가 드러납니다. 그 서버는 사용자의 IP 주소와 시각을 알게 되고, 페이지는 사용자의 브라우저에서
  실행됩니다. 데스크탑 앱에서는 기본 브라우저에서 열리므로, 그 브라우저의 프로필, 쿠키, 지문이 그대로
  나갑니다. 디팡된 채 저장된 URL에는 나오지 않습니다. 먼저 일부러 리팡해야 합니다.
- **Remove field…**는 노드의 유형이 선언하지 않은 필드의 메뉴 맨 끝에 나옵니다. 필드에 아무 값이
  없어도 나옵니다([필드 더하기와 지우기](#adding-and-removing-fields)).
- **Esc**는 메뉴만 닫고 그 뒤의 것은 닫지 않습니다. Review 대화상자에서도 메뉴나 URL 확인 창에서 누른
  키는 그 안에서만 동작합니다. Space는 스테이징된 행을 체크하지 않고 항목을 고르며, 확인 창의 Esc는
  리뷰를 닫지 않습니다.

텍스트 필드 하나에 담긴 목록은 행 아래 보기에서 항목마다 **⋯**가 따로 있습니다. 그래서 네임서버 하나를
따로 복사하거나 검색하거나 노드로 만들 수 있습니다.

메뉴는 그리드가 배지를 붙일 때, 그리고 AI 에이전트의 `extract_indicators`가 텍스트를 읽을 때와 같은
방식으로 값을 읽습니다. 그래서 그리드에서 `private`로 보이는 주소는 그쪽에서도 사설 주소로 보고됩니다.

*View only*로 표시된 패널에서도 메뉴로 복사, 검색, 노드로 이동, URL 열기를 할 수 있지만 새 노드는
제안하지 않습니다. 링크에 저장된 데이터에도 메뉴가 있으며, 거기서 만든 노드는 링크로 잇지 않습니다.
링크가 다른 링크에서 끝날 수는 없기 때문입니다. Review 대화상자에서는 복사와 URL 열기만 됩니다.

## 필드 더하기와 지우기 {#adding-and-removing-fields}

노드는 유형이 선언하지 않은 필드도 가질 수 있습니다. 플러그인이 이런 필드를 쓰며, 메모나 태그처럼
사용자가 직접 더할 수도 있습니다. Type Pack의 새 버전을 기다릴 필요가 없습니다. 그리드는 이런 필드를
유형이 선언한 필드 뒤의 **Added fields** 아래에 보여 줍니다([그리드](#the-grid)).

- 마지막 행 아래의 **+ Field**를 누르면 **Name**(이름), **Kind**(종류), **Value**(값)를 받는 입력
  양식이 열립니다. **Add field**를 누르면 필드가 바로 노드에 기록됩니다. 리뷰를 위해 스테이징되지
  않습니다.
- 이름은 영문 소문자, 숫자, `_`로 쓰고 영문자로 시작하며 31자까지입니다. Type Pack이 자기 필드
  이름에 따르는 규칙과 같으므로, 나중에 나온 팩 버전이 같은 이름으로 그 필드를 선언할 수 있습니다.
  `First Seen` 같은 이름은 거부되고, 옆에 **Use `first_seen`**이 나옵니다. 유형이 선언한 필드는 그
  행에서 채우고, 노드가 이미 가진 필드는 그 행에서 바꾸므로, 두 경우의 이름은 여기서 받지 않습니다.
- 이름 아래 **Suggested**에는 `notes`(Text)와 `tags`(Array)가 먼저 나오고, 같은 유형의 다른 노드가
  가진 미선언 필드가 많이 쓰인 순서로 이어집니다. 그래서 한 필드가 그래프 전체에서 한 이름을
  유지합니다. 이름을 누르면 그 이름과, 다른 노드들이 그 필드에 담은 종류가 채워집니다. 유형이
  선언했거나 노드가 이미 가진 이름은 제안하지 않습니다.
- 종류 이름은 Type Pack 스키마가 이 값들에 붙인 이름을 따릅니다. **Text**(`text`, 줄바꿈 유지),
  **Number**(`number`), **Boolean**(`boolean`), **Array**(텍스트 항목의 `array`. 하나를 입력하고
  **Enter**), **Object**(`object`, 중괄호 `{…}`로 씀)입니다. Object에 목록을 쓰면 Array를 쓰라는
  안내와 함께 거부되고, 숫자 목록은 노드의 [JSON 보기](#document-and-json-views)에서 쓸 수 있습니다.
  필드는 값과 함께 더합니다. 빈 텍스트, 항목이 없는 Array, `{}`는 거부됩니다. 아무것도 없는 필드는
  노드에 없는 필드처럼 읽히기 때문입니다. 정확히 저장할 수 없을 만큼 큰 숫자도 거부되므로, 자릿수를
  모두 지키려면 **Text**를 고르세요.
- 이름이나 숫자 입력칸에서 **Enter**를 누르면 필드를 더하고, JSON 편집기를 포함해 양식 어디서든
  **⌘Enter**(Mac)나 **Ctrl+Enter**로도 더할 수 있습니다. 이때 JSON에 줄바꿈이 들어가지 않고, 목록에
  입력하던 항목도 함께 들어갑니다.
  **Esc**나 **Cancel**은 양식을 닫고 입력한 내용을 버립니다. 더하기 전에 패널이 다른 노드로 옮겨
  가면 양식이 닫히고, 알림에 **Copy the value**가 나옵니다.
- 필드를 더할 때는 행에서 고친 변경이 저장되기를 기다린 뒤, 그 순간의 노드 `data`에 새 필드를 넣어
  기록합니다. 그래서 직전에 저장된 변경은 내 것이든 다른 사람 것이든 남습니다. 그사이 다른 사람이
  같은 이름의 필드를 더했다면 양식이 그렇다고 알리고 아무것도 쓰지 않습니다.
- 노드의 유형이 선언하지 않은 필드에는 값 메뉴(**⋯**) 맨 끝에 **Remove field…**가 있습니다. 필드에
  아무 값이 없어도 있습니다. 지우기 전에 확인을 받으며, 필드에 담긴 값을 보여 줍니다. 확인하기 전에
  필드가 바뀌면 새 값을 보여 주며 다시 묻고, 다른 사람이 이미 지웠다면 아무것도 쓰지
  않습니다. 더할 때처럼 행에서 고친 변경이 저장되기를 기다립니다. JSON 보기에서 지울 때처럼 노드의
  `data` 전체를 쓰므로, 같은 순간에 다른 사람이 저장한 변경은 사라질 수 있습니다.
- 유형이 선언한 필드는 행이 그대로 남습니다. 대신 값을 비우거나, 유형이 필수로 정하지 않은 필드라면
  JSON 보기에서 지우세요. 노드의 Type Pack이 설치되어 있지 않거나 불러오지 못했다면 Vineyard는
  유형이 어떤 필드를 선언하는지 알 수 없으므로 **Remove field…**를 보여 주지 않습니다. 이때도 JSON
  보기에서는 필드를 지울 수 있습니다.
- *View only*로 표시된 패널에는 **+ Field**가 나오지 않고, 어떤 필드도 지울 수 없습니다.

## 문서 보기와 JSON 보기 {#document-and-json-views}

노드 이름 아래의 **Table**, **Document**, **JSON**으로 패널이 노드를 보여 주는 방식을 바꿉니다. 고른
보기는 이 기기에 기억됩니다. **Table**은 [그리드](#the-grid)입니다. 캔버스에서 누른 **Enter**나
**F2**, 그리고 **G** 다음 **P**는 **Document**나 **JSON** 보기에서도 필드를 엽니다. 이때 패널은
**Table**로 바뀌고, 이 기기에 기억된 보기는 고른 그대로 남습니다.

**Document**는 노드를 읽기 위한 한 페이지로 보여 줍니다.

- 제목, 유형, 노드를 식별하는 필드가 먼저 오고, 한 줄짜리 값, 그다음 긴 값이 필드 이름 아래에
  하나씩 옵니다. 긴 텍스트는 줄바꿈을 지킨 문단으로, 규칙이나 원본 레코드는 코드로, 목록은 항목으로,
  JSON은 펼치기 전까지 한 줄로 접혀 보입니다. 선언되었지만 값이 없는 필드는 *Not collected*에 이름만
  적힙니다. 40줄이 넘는 값은 앞부분과 **Show all**을 보여 줍니다.
- **Source**에는 노드를 만든 시각과 마지막으로 바꾼 시각(UTC)이 표시됩니다. **Who created and changed
  it**을 누르면 각 작업의 계정을 활동 로그에서 읽어 옵니다. 노드를 선택할 때마다 읽지 않고 누를 때만
  읽습니다. 에이전트와 플러그인의 쓰기는 그 결과를 적용한 계정으로 기록됩니다. 로컬 모드와, 공개
  링크로 프로젝트를 연 계정에는 시각만 표시됩니다. 활동 로그는 프로젝트 멤버 전용이기 때문입니다.
  활동 로그를 읽지 못하면 그렇다고 표시하고 **Try again**을 보여 주며, 탭을 연 뒤 본 마지막 작성자가
  있으면 *In this session* 아래에 표시됩니다.
- **Links**는 노드에서 나가고 들어오는 링크를 라벨별로 묶고, 증거 등급마다 링크 수를 보여 줍니다.
  목록의 노드를 누르면 그 노드를 선택하고 캔버스 가운데로 옮깁니다.
- **Copy as Markdown**은 보고서에 옮길 수 있도록 이 페이지를 복사합니다. 모든 값과, 데이터에서 온
  이름(제목, 필드 이름, 링크 라벨, 계정 이름)은 코드로 적히므로 붙여 넣은 곳에서 링크, 이미지, 서식이
  되지 않고 줄바꿈도 지켜집니다. 시각은 "3h ago" 없이 UTC로 적힙니다. **Who created and changed it**의
  답을 받기 전에 복사하면, 활동 로그에서 이름을 읽지 않았다는 문장이 Markdown에 들어갑니다.

**JSON**은 노드의 `data` 전체를 들여쓴 JSON으로 보여 줍니다. **Tree**로 접고, 찾고, 키의
경로(`whois.events[0]`)를 복사할 수 있습니다. **Edit**를 누르면 JSON 편집기가 열리고, 여기서 필드를
바꾸거나 더하거나 지울 수 있습니다. WHOIS나 RDAP 레코드를 가진 노드는 8,000자 가까이 될 때가 많습니다.
편집기는 [JSON 값](#json-values)에서처럼 열 때의 크기로 강조할지를 정하므로, 원본 레코드를 지우거나
붙여 넣어도 커서 위치와 실행 취소를 잃지 않습니다.

- 저장할 때는 바꾸거나 더하거나 지운 필드만 씁니다. 손대지 않은 필드는 저장하는 순간 노드가 가진
  값을 그대로 두므로, 편집기가 열려 있는 동안 다른 사람이 그 필드를 바꿨다면 그 변경이 남습니다.
  편집기 위의 줄에 편집기를 연 뒤 바뀐 필드가 표시됩니다. 바꾼 내용을 다른 사람이 이미 모두 똑같이
  반영했다면 저장해도 아무것도 쓰지 않습니다.
- 저장이 필드를 지우거나, 편집기를 연 뒤 다른 사람이 바꾼 필드를 덮어쓰게 되면 먼저 확인을 받습니다.
  필드를 지우는 저장은 노드의 `data` 전체를 쓰므로, 같은 순간에 다른 사람이 저장한 변경은 사라질 수
  있습니다.
- 유형이 필수로 표시한 필드(`*`)는 지울 수 없습니다. 대신 다른 값을 넣으세요. 바뀐 값은 표에서처럼
  유형의 규칙으로 검사하며, 정확히 저장할 수 없을 만큼 큰 숫자는 따옴표로 감싸야 합니다.
- **Esc**나 바깥 클릭은 아무것도 입력하지 않았을 때만 편집기를 닫습니다. **Cancel**은 편집한 내용을
  버립니다. 저장이 진행 중일 때는 어떤 방법으로도 편집기가 닫히지 않습니다. 저장이 거부되거나(쓰기
  권한이 없는 경우) 실패하면 편집기가 이유와 함께 열린 채로 남으므로, 편집한 내용을 고치거나 복사할 수
  있습니다.
- 저장하지 않은 편집이 남아 있는데 패널이 그 노드를 떠나면(에이전트가 다른 노드를 선택했거나 다른
  사람이 이 노드를 지운 경우) 편집기는 저장하지 않고 닫히고, 알림에 **Copy your JSON**이 표시됩니다.
  편집기가 닫힌 뒤 실패한 저장도 같은 방식으로 알려 줍니다.
- *View only*로 표시된 패널에서는 **Edit**가 비활성화됩니다.

## 링크 {#a-link}

캔버스에서 링크(엣지)를 클릭하면 패널에 나옵니다. 위쪽에는 그 링크가 무엇이고 얼마나 믿을 수
있는지가 나옵니다.

- 양 끝 노드의 이름(`from → to`)과 링크의 **ID**.
- 라벨을 쓴 쪽:
    - *Edited here*: 사람입니다. 링크를 직접 그렸거나, 이 패널에서 라벨을 바꿨거나,
      [값 메뉴](#the-value-menu)에서 만들었습니다.
    - *Written by the assistant*: AI 에이전트입니다.
    - *Written by*와 플러그인 식별자(예: `run.vineyard.plugins.crtsh_subdomains`): 그 플러그인입니다.
    - *Original label*: 누가 썼는지 기록이 없습니다. 앱이 이를 기록하기 전에 쓰인 링크가 그렇습니다.
- *Evidence:* 등급과 그 등급을 매긴 쪽, 그리고 그 아래 한 줄로 등급의 뜻([증거 등급](#evidence-grades)).
  매긴 쪽은 *Graded here*(사람. 값 메뉴에서 만든 링크도 이렇게 표시됩니다), *Graded by the
  assistant*, *Graded by*와 플러그인 식별자, *Graded by a re-verification*(적용한
  [Re-verify](#re-verify)), *Graded by a merge*(합친 노드의 작성자가 같은 링크를 그려서 올라감.
  [노드 병합](canvas.md#merging-nodes) 참조), *Nobody graded this*(등급이 없는 파일에서 가져오기로 들어옴), *Grader not
  recorded*(앱이 매긴 쪽을 기록하기 전에 매겨짐) 가운데 하나입니다. 등급을 기록하기 전에 쓰인
  링크에는 *Evidence* 줄이 없습니다.
- **Re-verify**와 그 옆의 **Re-collect with the agent**([Re-verify](#re-verify)).

그 아래에는 프로젝트를 편집할 수 있을 때 바꿀 수 있는 두 값이 있습니다.

- **relation**은 링크의 라벨입니다. 두 노드를 잇는 것을 결론이 아니라 증거로 적습니다. 저장하면
  캔버스의 라벨이 바뀌고 *Edited here*로 표시됩니다. 라벨은 1,024자까지 저장되며, 빈 라벨은 *A link
  needs a label saying what connects the two.*와 함께 거부됩니다. **Stop and ask before anything is
  removed or overwritten**이 켜져 있는 동안(직접 끄지 않았다면 켜져 있습니다)에는 자동으로 적용되는
  AI 에이전트의 변경이 사람이 쓴 라벨을 바꾸려 하면 검토를 위해 멈춥니다([AI 에이전트 설정](tasks.md#review-and-apply)).
- **confidence**는 이 링크를 보증하는지입니다. 사람이 말할 수 있는 두 등급 **asserted**와
  **unassessed** 가운데 고릅니다. 나머지 등급은 검사나 도구가 무언가를 했다는 뜻이므로 제시하지
  않습니다. 링크가 그런 등급을 가졌으면 목록에 보이며, 그것을 다시 골라도 아무것도 쓰지 않습니다. 고른
  등급은 *Graded here*로 표시됩니다. 등급을 바꿔도 라벨이 내 것이 되지 않고, 라벨을 바꿔도 등급을 매긴
  쪽은 바뀌지 않습니다.

링크 패널에는 찾기 칸과 **Hide empty**가 없습니다.

### 링크와 함께 기록된 값 {#recorded-with-this-link}

**Recorded with this link** 아래에는 링크에 저장된 나머지 값이 모두 나오며, 누구에게나 읽기
전용입니다. 링크를 그린 플러그인이나 에이전트가 함께 기록한 값으로, 링크를 어디서 언제
관측했는지 같은 것입니다. 예를 들어 OTX Passive DNS는 `source`, `record_type`, `first_seen`,
`last_seen`을 저장합니다. 같은 링크를 함께 그린 다른 작성자를 담은 `corroborated_by`도 이 목록에
나오며, 증거 등급은 이것을 셉니다. 직접 그린 링크처럼 더 저장된 값이 없으면 *Nothing else is
stored with this link.*가 표시됩니다. 적용을 기다리는 링크에는
[Review 대화상자](running-plugins.md#reviewing-a-runs-changes)가 같은 목록을 보여 줍니다.

### 증거 등급 {#evidence-grades}

모든 링크에는 그 증거가 어디까지 가는지를 말하는 등급이 하나 있습니다. 캔버스는 등급마다 다른 선으로
그리고, 범례의 **Evidence** 키가 프로젝트에 있는 등급을 나열합니다([범례](canvas.md#범례)). 강한
순서대로:

| 등급 | 뜻 | 어디서 오는가 |
|---|---|---|
| `assessed` | 독립 검사가 이 링크를 반박해 보았고, 링크가 버텼습니다. | 독립 검사, 또는 적용한 재검증 |
| `asserted` | 사람이 이 링크를 보증했습니다. 분석가의 판단이지 측정이 아니며, 무언가가 링크를 검사했는지는 말하지 않습니다. | 사람. 직접 그린 링크는 이 등급으로 시작합니다. |
| `recorded` | 도구가 기록했습니다. 한쪽 끝의 필드가 다른 쪽을 가리키거나, 수집기가 찾은 것을 자기가 찾지 않은 노드에 이었거나(DNS 조회가 도메인을 그것이 가리키는 IP에 이은 링크), 서로 독립인 수집기 둘이 같은 링크를 그렸습니다. 검증되었다는 뜻이 아닙니다. | 플러그인이나 에이전트의 변경 적용, 또는 값 메뉴에서 만든 링크. 적용한 것이 나이므로 *Graded here*로 표시됩니다. |
| `circumstantial` | 검사했고 들어맞지만, 같은 증거에 무해한 설명도 들어맞습니다. | 독립 검사, 또는 재검증 |
| `contested` | 검사가 이 링크를 거부했습니다. 사람이 남겨 두었기 때문에 여기 있습니다. 주황색으로 더 굵게 그립니다. | 독립 검사, 또는 재검증 |
| `unassessed` | 이 링크에는 검사되었다는 기록이 없습니다. | 아무것도 검사하지 않은 변경의 적용, 또는 `asserted`를 거둬들인 사람 |

등급은 매겨진 때 알려져 있던 것을 기록합니다. 링크 주변의 그래프가 커져도 저절로 바뀌지 않고,
사람이나 검사, 또는 그 링크의 새 증거를 가져온 나중의 실행이 링크를 다시 쓸 때만 바뀝니다. 일부러
다시 물으려면 **Re-verify**를 씁니다. 어떤 등급도 링크를 편집하거나 지우거나 그 위에 쌓는 것을 막지
않습니다. 독립 검사는 AI 에이전트 설정의 **Have an independent check test each inference**입니다
([AI 에이전트 설정](tasks.md#review-and-apply)).

### Re-verify {#re-verify}

**Re-verify**는 독립 검사에게 이 링크를 지금 기준으로 다시 판단하게 합니다. 라벨, 양 끝이 기록한 값,
양 끝에 그래프가 가진 그 밖의 것(이 링크 자체는 빼고), 라벨을 쓴 쪽, 기록된 등급과 매긴 쪽, 같은
링크를 그린 다른 수집기, 링크가 얼마나 오래되었는지를 읽습니다. [AI 에이전트](tasks.md#the-ai-agent-panel)에 설정한 키로 모델
제공자에게 묻습니다. 키가 없으면 버튼이 그렇다고 알리고 아무것도 하지 않습니다.

검사는 아무것도 쓰지 않습니다. 판정은 *Re-verification*이라는 이름의 변경 세트로 스테이징되어 Review
대화상자에 열리고, Tasks 창에 그 행이 남습니다. 리뷰에는 `supported — still valid`나 `refuted — stale`처럼
검사가 링크를 어떻게 보았는지가 나오며, 적용하면 등급이 다음처럼 정해집니다.

| 판정 | 등급 |
|---|---|
| *still valid* | `assessed` |
| *stale* | `contested` |
| *inconclusive* | `circumstantial` |
| *not checked*: 검사를 실행하지 못했으며, 알림이 이유를 알립니다 | 내려가지 않으며, `contested`는 그대로입니다. 다른 갱신과 마찬가지로, 한쪽 끝의 필드가 다른 쪽을 가리키거나 다른 수집기가 같은 링크를 그렸다면(`corroborated_by`) `recorded`로 올라갈 수 있습니다. |

재검증은 링크 삭제를 제안하지 않습니다. 검사에는, 다시 확인하지 못한 링크라고 해서 거짓인 것은
아니니 증거가 이제 링크와 어긋나지 않는 한 *stale*이 아니라 *inconclusive*로 답하라고 알려 줍니다.
사라진 페이지나 한 번 실패한 조회는 낡았다는 증거가 아닙니다. 검사가 반박한 링크도 `contested`로
그래프에 남고, 지우는 것은 사람의 몫입니다. 재검증을 적용해 등급이 바뀌면 그 등급은 *Graded by a
re-verification*으로 표시되고, 등급이 그대로이면 매긴 쪽도 그대로입니다. 검사한 뒤 라벨이 바뀐
링크에는 판정을 적용하지 않습니다. 재검증이 검토를 기다리는 동안 버튼은 **Review re-verification**으로
바뀌고, 누르면 그 리뷰가 열립니다.

버튼 옆 화살표에는 **Re-collect with the agent**가 있습니다. 이 링크의 새 증거를 모으고 바꿀 것이
있으면 리뷰를 거쳐 제안해 달라는 요청이 채워진 새 AI 에이전트 대화가 열리며, 요청은 보내지 않습니다.
읽고 보내기 전에는 아무것도 실행되지 않습니다.
